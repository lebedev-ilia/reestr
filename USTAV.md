# Устав реестра

Реестр переживает системы агентов. Система — третья по счёту, реестр — один.
Поэтому здесь нет ничего, что зависит от конкретной системы: только файлы,
SQLite и Python из стандартной поставки. Ни服务, ни базы снаружи, ни ключей.

---

## Два слоя, и их нельзя путать

**`syroe/` — сырое. Только дописывается, никогда не правится.**
Это свидетельство: что было сказано и сделано, дословно. Если сырое можно
править, оно перестаёт быть доказательством и превращается в ещё одну версию
событий.

**`zapisi/` — осмысленное. Правится и устаревает.**
Это выводы: уроки, решения, факты, люди, клиенты. Каждая запись обязана
указывать на сырое, из которого выросла.

Правило, из которого всё следует: **вывод без указателя на свидетельство —
это мнение.** Через год отличить одно от другого будет нечем, кроме этой
ссылки.

---

## Разделы `zapisi/`

| Раздел | Что туда | Признак |
|---|---|---|
| `lyudi/` | Люди: кто, чем занимается, как с ним работать | Про человека |
| `klienty/` | Заказчики, сделки, переписка по деньгам | Есть деньги или обязательство |
| `proekty/` | Проекты и их состояние | Есть начало и конец |
| `uroki/` | Ошибки и что из них следует | Было больно, повторять не хочется |
| `fakty/` | Проверенные сведения с источником | Можно перепроверить по ссылке |
| `resheniya/` | Принятые решения и их причина | Было несколько путей, выбрали один |
| `zhizn/` | Личное: здоровье, деньги, обязательства, сроки | Про Илью, а не про дело |

Не подходит ни один — значит, это пока сырое. Не выдумывай раздел.

## Обязательная шапка записи

```markdown
---
imya: kratkoe-imya-v-latinice
data: 2026-09-28
tip: urok | fakt | reshenie | chelovek | klient | proekt | zhizn
istochnik: syroe/besedy/2026-09/2026-09-28__<сеанс>.jsonl.gz
metka: <uuid хода>          # если известен
godnost: bessrochno | do-2026-12-31
tegi: [prokси, ceny]
---
```

**`godnost` — самое недооценённое поле.** Цена прокси, ставка рынка, состояние
проекта устаревают. Запись без срока годности через год врёт с той же
уверенностью, с какой год назад говорила правду.

---

## Как писать, чтобы нашлось через год

1. **Первая строка — вывод, а не предыстория.** Поиск отдаёт выдержку
   в двести знаков; если в них вступление, попадание бесполезно.
2. **Называй вещи так, как их назовёт ищущий.** Не «оптимизация канала
   привлечения», а «отклики на FL.ru».
3. **Числа с единицами и датой.** «180 000 ₽/мес, сентябрь 2026», а не
   «около ста восьмидесяти».
4. **Одна запись — одна мысль.** Две мысли в одном файле означают, что
   вторую никто не найдёт.
5. **Связывай записи** через `[[imya]]`. Связи дешевле оглавлений
   и не устаревают.

## Как пользоваться

```bash
# найти (отдаёт выдержки и указатели, не документы целиком)
python3 sluzhba/nayti.py "прокси Владивосток"
python3 sluzhba/nayti.py "цена" --razdel resheniya --s 2026-09-01

# прочитать источник целиком, по указателю из выдачи
python3 sluzhba/nayti.py --pokazat syroe/besedy/2026-09/....jsonl.gz --metka <uuid>

# обновить вручную (обычно это делает крючок сам)
bash sluzhba/obnovit.sh
```

**Порядок работы агента с ограниченным контекстом:** сначала поиск, он дёшев
и отдаёт короткое. Потом — чтение одного источника по указателю, и только
того, который действительно нужен. Никогда не читать сырое целиком:
там восемнадцать тысяч ходов.

---

## Что делает служба сама

- **Приём.** Крючок `Stop` в `~/.claude/settings.json` после каждого ответа
  запускает `sluzhba/obnovit.sh`: новые беседы попадают в сырое, указатель
  перестраивается. Ничего не надо помнить.
- **Затирание секретов.** Ключи, приватные ключи и куки затираются на входе
  с пометкой `[СЕКРЕТ ЗАТЁРТ <признак>]`. Беседа при этом сохраняется целиком:
  терять историю нельзя, выпускать ключ наружу тоже.
- **Отбор повторов.** При продолжении сессии Claude Code копирует историю
  в новый файл. Указатель берёт первое вхождение по `uuid` — без этого
  три четверти выдачи были бы повторами.

## Чего в реестре не должно быть

- Паролей, ключей, доступов — никогда, даже в закрытом хранилище.
  Закрытость репозитория это настройка, а не защита: `TrendFlowML` был закрыт
  в августе и снова открыт к сентябрю, чего никто не заметил.
- Персональных данных третьих лиц без основания.
- Рассуждений вслух — в сырое идут сообщения и действия, не размышления.
- Производных файлов. `ukazatel/reestr.db` строится из сырого за минуту
  и в git не хранится.
