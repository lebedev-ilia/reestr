# ПРОИЗВОДНОЕ. Владелец: агент.

Всё здесь пересобирается из `memory/log/` и внешних источников. Может быть
снесено целиком в любой момент — код обязан пережить пустой `derived/`.
В гит не идёт (`.gitignore`) — кроме этого файла. Уникального здесь не хранить.

Исключение сделано для карты: она описывает зону, а после сноса зоны её нечем
было бы восстановить — единственный уникальный файл здесь оказался бы сам этот
README (bl-032). С 24.08 он под гитом (`derived/*` плюс `!derived/README.md`),
и снос лечится одной командой:

    git checkout -- derived/README.md

Правится он в этой же папке, как обычный файл репозитория: второй копии в
исходной зоне нет намеренно — две копии молча разъезжаются. Целость проверяет
самотест ядра (`test_zones`): карта на месте, под гитом, остальное в зоне — нет.

README в подкаталогах не нужен: каталоги заводятся кодом на ходу, карта — здесь.

## Что где живёт

- `index/` — поисковые индексы (recall). Пересобираются из лога.
- `fs/index.db` — индекс файлов ПК: имена и метаданные, содержимого в нём нет.
  Пересобирается `python -m jarvis.modules.fs.index build` (минуты), догоняется
  `… update` (секунды). См. `modules/fs/README.md`.
- `rollups/` — свёртки дней, недель, месяцев. Пишет ночной цикл.
- `threads/` — досье по контактам рассылки: файл на адрес плюс сводка
  `INDEX.md`. Пересобирается `python3 -m modules.outbox.history` из
  `memory/outbox/sent.jsonl` и `replies.jsonl` — целиком, побайтово так же.
  Уникального в нём нет по построению, каталог перед сборкой вычищается.
- `selftest/log/` — куда уезжают записи самотестов: пока поднят флаг
  `C.SELFTEST`, `memory.log()` пишет сюда, а не в живой `memory/log` (bl-061,
  правило `samotest-ne-pishet-v-zhivuyu-pamyat`). Мусор по построению, сносится
  не глядя.
- `steps/` — пошаговый журнал ходов, по файлу на день. Отладка, читается редко.
- `jobs/` — сырой вывод процессов-подагентов, по файлу на задание
  (`<job-id>.log`). Отладка «почему задание упало», читается редко и сносится
  не глядя. Сами задания — бриф, статус, результат — живут в `memory/jobs/`:
  их не пересоздать ничем.
- `notion/` — снимок воркспейса Notion (`raw.json`, `workspace.md`).
  Пересобирается `python -m jarvis.modules.notion.dump`. Журнала правок здесь
  больше нет: он уникален и с 24.08 живёт в `memory/notion_writes.jsonl`.
- `vk_media/` — вложения из ВК по папке на день. Чистятся через 30 дней
  (`modules/vk/daemon.py`, `prune_media`). Оригиналы остаются в переписке.
- `voices/` — голоса Piper, 60 МБ на голос (ruslan рабочий, denis и dmitri
  остались от выбора 22.08). Возврат: `python3 -m jarvis.modules.voice.fetch`
  (только ruslan), `… fetch --all` (все три), `… fetch --check` (жива ли
  ссылка, ничего не качая). До 26.08 команды не было вовсе — say.py обещал
  «скрипт ниже», а скрипта не существовало (bl-051).
- `stt/` — модель faster-whisper-small, 464 МБ. Возврат: сама, при первом же
  распознавании голосового (~1,5 минуты, строка `stt_download` в логе).
  Канал у Ильи слабый: обе папки сносить только осознанно, места они не жмут —
  на диске 48 ГБ свободно.
- `hh_profile/` — профиль Chromium с живой сессией hh.ru (16 МБ). Возврат:
  повторный вход по процедуре `vhod-hh-cherez-pochtu` — нужен код с почты, то
  есть минуты и внимание. Лежал в `scratch/` до 26.08, где его снесла бы
  плановая чистка; вынесен отдельным каталогом ровно поэтому.
- `drafts/<роль>/` — черновики ролей: соберутся заново той же ролью. Черновики,
  показанные Илье и ждущие его «да», здесь не живут: их правки существуют в
  одном экземпляре, им место в `memory/drafts/` (bl-051).
- `scratch/<дата>-<зачем>/` — рабочий стол на один ход: копии файлов перед
  рискованной правкой, одноразовые репозитории для проверки хуков, пробники.
  Здесь живёт то, ради чего иначе потянулся бы за `git stash` (он запрещён,
  правило `git-stash-zapreshchen`) или за `/tmp` (шлюз туда не пускает,
  правило `odnorazovye-proverki-v-derived`). Настоящий `.env` сюда не копировать
  — подставлять синтетическое значение той же длины и вида.
  Убирается САМА, ночным циклом (`core/scratch.py`, bl-085): запись, которую не
  трогали трое суток, удаляется, а файл, брошенный не в каталог, а прямо в
  корень, через сутки переезжает в `<дата>-rossyp/` и стареет там. Итог уборки —
  строка `scratch_prune` в логе; посмотреть, что уйдёт, не удаляя:
  `jarvis/.venv/bin/python -m jarvis.core.scratch`. Нужное дольше трёх суток
  здесь не держать — это зона одноразового, а не хранилище.
- `git-backup-<дата>/` — копия `.git` и снимок `memory/log` перед переписыванием
  истории. Снимать только после того, как Илья подтвердил, что история цела.
- `*.json`, `*.lock`, `*.log` в корне — состояние демонов: где остановился
  ночной цикл, докуда прочитан ВК, когда был последний пульс. Пропажа безопасна:
  ночь догонит пропущенное, ВК начнёт с текущего сообщения.
- `system_prompt.<pid>.txt` — слепок системного промпта хода, для замера длины.
  Чистится САМ, раз в час тактом демона ВК (`modules/vk/daemon.py`,
  `prune_derived`, bl-098): уходит слепок старше суток, чей процесс уже мёртв;
  слепок живого хода не трогается ни в каком возрасте. До 27.08 слепки
  копились молча и вычищались руками.
- `selftest/log/<дата>.jsonl` — куда уходят записи прогонов самотеста, чтобы не
  пачкать живой лог. Тем же тактом `prune_derived` сносятся дни старше трёх
  суток — не «целиком»: 26.08 туда утекли настоящие строки живого лога
  (факт `log-uehal-v-derived`), и запас в трое суток даёт время их вернуть.

## Правила зоны

Одноразовое (проверки, песочницы, скрипты на один запуск) кладётся сюда и
сюда же умирает. Понадобилось надолго — значит место не здесь, а в исходной зоне.

Скрипт отложенного перезапуска демона ВК (`restart_vk.sh`) собирается заново
под конкретный pid при каждой правке кода канала; шаблон — в процедуре
`perezapusk-demona-vk`, а не в этой папке.

Нарушение, найденное и закрытое 24.08: журнал «как было» для отката правок
Notion лежал здесь (`notion/writes.jsonl`), хотя восстановлению не подлежит.
Уведён в `memory/notion_writes.jsonl`. Проверка перед записью сюда любого
файла — правило `v-derived-tolko-vosstanovimoe`: назови команду, которой
файл вернётся после сноса зоны; не называется — ему тут не место.
