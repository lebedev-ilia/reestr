## 1. Собственная роль критика получила задание, которое ей же запрещено выполнять
- **что**: `memory/agents/critic/ROLE.yaml`, строки 38-42 — задача роли прямым
  текстом требует: «Начни с того, что смотреть: git log и git diff за период
  (команды только на чтение)». Но шлюз `core/agent.py`, функция `outside_zone`
  (строки 1036-1042), для любой роли с зоной пропускает через Bash только
  команды, прошедшие `SAFE_BASH`, и `git log`/`git status`/`git diff` в это
  сито не проходят вовсе — не потому что они пишут (ZONE_BASH_WRITE ловит
  только `git add|commit|checkout|reset|clean|push`), а потому что сам
  `SAFE_BASH` их не знает. На практике в этом же ходе три попытки подряд
  (`git log`, `git -C ... log`, `git status`) отклонены одним и тем же
  сообщением «шелл её не соблюдает… оставь для чтения (ls, cat, grep, find)».
- **почему плохо**: роль, чья единственная работа — читать историю изменений,
  не может прочитать git log и git diff вообще ни разу. Это не «зона», это
  дыра в списке разрешённых команд: git log/show/diff/status ничего не пишут
  и должны быть безопасны так же, как cat и grep. Каждый час критик будет
  начинать с провала первого же шага из собственного задания и подменять его
  чтением файлов по mtime — то есть задание в ROLE.yaml обещает то, чего код
  не даёт сделать.
- **что делать**: добавить в `SAFE_BASH` (core/agent.py) чтение-only git:
  `git log`, `git diff`, `git show`, `git status`, `git blame` — по образцу
  того, как уже разрешены `ls/cat/grep/find`. Либо переписать текст задачи в
  `critic/ROLE.yaml`, если git-историю решено не давать ролям с зоной вовсе
  (тогда обещание в задаче — ложное и его надо снять).
