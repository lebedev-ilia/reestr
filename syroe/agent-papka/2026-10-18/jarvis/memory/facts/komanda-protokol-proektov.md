ГЛАВНОЕ: свод решений Ильи от 26–27.08.2026 лежит ОТДЕЛЬНЫМ ДОКУМЕНТОМ вне
репозитория агента — /home/ilya/Рабочий стол/Agent/Джарвис-команда-и-проекты.md.
Это решения, а не предложения. Любая работа по командам, тимлидам, протоколу
задач, сводкам, обкатке и проекту No Logo начинается с чтения этого файла
целиком, а не с этого факта: здесь только карта и состояние стройки.

ЧТО В ДОКУМЕНТЕ (19 разделов): три уровня (Илья → Jarvis → команда проекта);
Jarvis НЕ УЧАСТВУЕТ В ПРОИЗВОДСТВЕ — он ставит цель тимлиду, отвечает на
эскалацию, отдаёт сводку Илье, остальное время свободен, потому что он один
последовательный процесс и станет горлышком на пяти проектах. Протокол задачи —
три файла с разными владельцами (task.md тимлида, потолок 100 строк; task.json
критерии с passes, статус меняет только тимлид; progress.md исполнителя).
Тимлид — постоянный процесс со сторожем живости, исполнители — одноразовые.
Доказательство выполнения по цене ошибки: артефакт, критерии, машинная проверка,
перепроверка вторым агентом для всего, что уходит наружу; юрист запускается по
типу артефакта, а не по чутью. Память проекта — memory/projects/<проект>/,
факты о клиенте остаются в общей памяти. Сводки: 8:00, каждый час 9–21, 22:00,
цифры собирает код, формулирует haiku. Откат: чинить разрешено, только если
можешь назвать границы ошибки. Ветки agent/<id задачи>, слияние — тимлидом
после приёмки.

ПОРЯДОК СТРОЙКИ (раздел 19). Этап 0 — Jarvis строит протокол в одиночку, на
проекте-полигоне memory/projects/vnutrennii, чтобы nologo оставался чистым.
Этап 1 — команда строит страницу состояния (раздел 15). Этап 2 — команда
репетирует пилот No Logo на семи шагах, присланных Николаем. Признак
готовности: прогон от начала до конца, результат совпал с заранее написанным
ожиданием, участие Ильи минимально, роли координировались правильно. Протокол
выпускается на клиента только после этого — первый платящий заказ не полигон.

ОСОБАЯ ОГОВОРКА ИЛЬИ, которая касается меня лично: Jarvis строит систему,
которая будет его же и контролировать (счётчики, шлюзы, потолки, Критик).

когда всё остальное делается самостоятельно. Причина названа прямо: в моменте
всегда кажется разумным сделать ограничение помягче — так уже случилось с

ЧТО ВЫЯСНИЛОСЬ НА ПЕРВОЙ ЖИВОЙ ЗАДАЧЕ (t-002, приёмка 30.08):
— Тимлиду-роли доступен из кода только `jarvis.modules.projects.cli`; любой
  другой модуль агента (например `jarvis.modules.status.*`) для роли закрыт
  целиком. Следствие: критерии вида «команда отрабатывает» тимлид своей рукой
  проверить не может и вынужден зачитывать их по косвенным уликам, отмечая это
  оговоркой в task.json. Проверку запуском делает Jarvis или сам исполнитель.
— Файл `memory/projects/<проект>/backlog.md` не удаляется ни одной ролью:
  общий шлюз блокирует запись в любой файл с таким именем, где бы он ни лежал.
  Старый backlog.md рядом с queue.md даёт раздвоенную очередь и красный
  самотест проекта. Снять может только Илья.
— Задача, заведённая тимлидом, не стартует сама: живого исполнителя запускает
  Jarvis заданием (правило zadacha-timlida-ne-startuet-sama).
— План проверки исполнителя визируется тимлидом ДО работы, а работа идёт в
  ветке agent/<task>-<кратко>. На t-002 не соблюдено ни то, ни другое —
  отклонения записаны в журнал роли; с t-003 оба пункта обязательны.
