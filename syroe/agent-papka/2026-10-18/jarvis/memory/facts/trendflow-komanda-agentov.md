Каталог: /home/ilya/Рабочий стол/TrendFlowML/automation. Работал с 12.07 по 24.08.2026,
23–27.08 стоит на паузе по решению Ильи. Это не прототип: 1010 задач на доске, 894 закрыты,
1047 отчётов, 219 вопросов владельцу, 1785 записей расхода.

ЗАЧЕМ ЭТО МНЕ. 25.08.2026 Илья поправил моё понимание управления агентами: я буду управлять
не подагентами-однодневками, а многими ПОЛНОЦЕННЫМИ агентами, каждый строго на свою область.
Образец устройства — этот проект.

УСТРОЙСТВО
- Один постоянный процесс: supervisor.py (94 КБ) под systemd (trendflow-team.service,
  Restart=always). Сам работу не делает — поднимает роль как отдельную сессию Claude Agent SDK
  под конкретную задачу и гасит после неё. Роль живёт один ход, не постоянно.
- Чата между агентами нет вовсе. Всё общение через файлы в board/: tasks/, reports/,
  questions/, decisions/, handoffs/, incidents/, proposals/. Правило: у каждого файла ровно
  один автор. Обоснование в board/README.md: так обмен воспроизводим, отлаживаем и не жжёт лимит.
- Роль описана каталогом agents/<role>/: ROLE.yaml (зона owns, модель, потолок ходов, доля
  бюджета), PROMPT.md, STATUS.md, LESSONS.md, journal/.
- Границы зон держит КОД, а не промпт: core/permissions.py вешает хуки PreToolUse и Bash.
  make_write_guard сверяет путь записи с owns роли; make_bash_guard ловит force-push, rm -rf,
  DROP TABLE, тяжёлые локальные вычисления и обход через >, tee, sed -i в чужую зону.
  Линтер проверяет, что зоны owns разных ролей не пересекаются.
  core/permissions.py агенты править не могут вовсе — только человек.
- Общий контекст каждой сессии — OWNER_BRIEF.md: фокус месяца, деньги, лимит, стоп-лист
  «только через владельца», накопленные уроки. Правит только Илья.
- Маршрутизация тем — core/COMPETENCY_MAP.yaml: ключевые слова → роль. Тема не опознана —
  не гадать, спросить владельца.
- Два режима сессии: answer (опрос эксперта, 3–5 ходов, дешёвая модель, запись и Bash
  физически недоступны) и work (полная сессия с правом писать в свою зону).

РОЛИ (16): dispatcher (тимлид, opus, 40 ходов), reviewer (ревизия команды, проверяет отчёты
по факту, а не на слово, 20% бюджета), backend, devops (владеет ядром автоматизации),
qa, researcher, component_engineer, ml_engineer (выделен 14.08 из component_engineer из-за
перекоса 387 против 132 минут за вечер), data_collector, frontend, designer, analyst,
marketer, legal, security, archivist. Отдельно general_agent/ и site_agent/ — более ранние
одиночные агенты, предшественники схемы; fetcher/ — демон сбора данных вне схемы.

БЮДЖЕТ. core/limits.py считает СЫРЫЕ токены вывода, без весов по моделям: калибровка через
минуты и веса трижды расходилась с реальным расходом аккаунта, вплоть до трёхкратной ошибки.
Недельный потолок 17,6 млн токенов (пересчёт из «5 часов Claude»), рабочий стоп 95%, жёсткий
97%, резерв 97–100 не трогается. Есть CircuitBreaker. За неделю W34 счётчик показывает 100%.

НАДЁЖНОСТЬ. Падение роли возвращает задачу в очередь и не считается провалом. Есть возврат
из blocked, поиск осиротевших задач, проверка застрявших, файл-лок на единственный экземпляр
супервизора, сторож главного цикла, автоперезапуск при изменении ядра, контроль глубины
каскада подзадач. Роль, упавшая три раза подряд, отключается до вмешательства владельца.

ЧТО ЛОМАЛОСЬ (ценнее всего)
- 20.08: сняли защиту от лишних экземпляров супервизора, не разобравшись, зачем она. Команда
  встала на 10 часов — это была единственная защита от другой поломки. Отсюда их правило
  «5-бис: проверяй всё» — умолчание, а не пожелание.
- Ночь 14.08: команда стояла 8 часов, потому что доска опустела, а ответов владельца не было.
  Лекарство — BACKLOG.md, резервный список работ на простой.
- Пять ролей упали в одну секунду с exit code 129 при столкновении с локом экземпляра.
- CLIConnectionError «Argument list too long» — SDK не мог запустить CLI. Та же болезнь, что
  была у меня с системным промптом.
- «JSON message exceeded maximum buffer size of 1048576 bytes» — SDK не тянул большой ответ.
- Сессия перевалила 40 минут и была прервана по таймауту.
- Приёмка врала: reviewer в STATUS.md пишет про 4-й и 5-й случай расхождения вердикта с тем,
  что реально на диске, за двое суток; причина не выяснена.
- marketer и ml_engineer без токена ВК — их сообщения уходят в лог и пропадают. Известный,
  но не закрытый дефект.
- LESSONS.md разрослись: у dispatcher 271 КБ, у devops 165 КБ. Консолидация не поспевает.
