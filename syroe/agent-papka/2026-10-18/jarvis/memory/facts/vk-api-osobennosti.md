Сверено 22.08.2026 по референсным библиотекам (vk_api, vk-io):
сам dev.vk.com из-под агента недоступен — WebFetch его не берёт,
документацию приходится добывать через код библиотек и схему VKCOM/vk-api-schema.

Bots Long Poll: ответ содержит ts + updates, либо failed.
failed=1 — ts устарел, новый ts лежит в том же ответе;
failed=2 — протух ключ, перезапросить сервер, ts сохранить;
failed=3 — потеряна информация, перезапросить сервер и взять новый ts.

С версии Long Poll 5.103 сообщение лежит в object.message; в версиях младше —
прямо в object. Версию выбирает владелец сообщества в настройках, и ошибка
там выглядит как «бот молчит»: события идут, сообщений ноль. Принимать обе формы.

Поля transcript и transcript_state у audio_message в официальной схеме
ОТСУТСТВУЮТ. Они работают, но недокументированы, то есть могут исчезнуть
без предупреждения. Опираться на расшифровку ВК как на единственный способ
понять голосовое — нельзя.

ПОДТВЕРЖДЕНО ВЖИВУЮ 22.08.2026: короткое голосовое (~3 с, русский, чистая
запись) расшифровалось, текст дошёл до промпта дословно, ожидание уложилось
в отведённые шесть попыток. То есть механизм работает — но проверен пока
только на лёгком случае. Что НЕ проверено: длинная запись, шум, смешанные
языки, поведение при transcript_state=in_progress дольше полуминуты.

Ошибки messages.send, о которых надо говорить вслух, а не глотать:
7 — нет прав у ключа; 9 — флуд-контроль; 901 — нельзя писать первым
(человек должен сам написать сообществу); 914 — сообщение слишком длинное.
Предел длины ~4096 символов, режем по 4000.
