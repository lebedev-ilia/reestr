## Что можно самому
— Ввести необязательное поле проекта: в строке очереди backlog, в задании подагента (memory/jobs/<id>/job.json — поле `project`) и в переменной окружения JARVIS_PROJECT, которая уже понимается зоной шлюза. Без метки всё работает как раньше — это обязательное требование обратной совместимости.
— Научить очередь фильтровать и показывать задачи по проекту.
— Ветки: завести на задачу ветку `agent/<t-NNN>-<короткая-транслитерация>`, проверять, что исполнитель не в основной ветке, при приёмке тимлидом сливать ветку в основную сообщением с id задачи. Слияние делает только роль тимлида — так же, как accept в modules/projects/tasks.py проверяет роль кодом, а не доверием. Проваленная задача остаётся невлитой веткой.
— Все проверки веток — на ОДНОРАЗОВОМ тестовом репозитории в derived/scratch/, никогда на рабочем репозитории агента.
— Свои проверки положить в modules/jobs/selftest.py и/или modules/projects/branches_selftest.py — свой файл, не чужой. Красные и зелёные случаи: слияние из роли исполнителя отбивается; слияние без id задачи в сообщении отбивается; задача без метки проекта работает как раньше.
— Коммитить только свои файлы; если тронул ядро (core/jobs.py — ядро) — в том же ходе дозаписать строку в конец memory/core_changes.md одной операцией дозаписи.

## Критерии приёмки
1. Метка проекта проставляется и читается у задачи очереди и у задания подагента; без метки поведение прежнее и ничего не сломано.
2. Очередь умеет показать задачи одного проекта.
3. Есть команда завести ветку на задачу и команда слить её при приёмке; слияние вне роли тимлида и слияние без id задачи в сообщении отбиваются кодом.
4. Проверки прогнаны на одноразовом репозитории в derived/scratch, рабочий репозиторий агента при этом не переключался и не откатывался.
5. Свой самотест зелёный по коду возврата; общий `./jarvis --selftest` после правок зелёный.
6. Свои файлы закоммичены, чужие не тронуты; если тронуто ядро — строка в memory/core_changes.md с коммитом и откатом.
