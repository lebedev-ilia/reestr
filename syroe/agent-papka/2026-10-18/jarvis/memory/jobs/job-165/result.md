# УНЭП через Госключ для NDA с No Logo — осуществимость и порядок действий

## Вывод в 5 строк

Прямой ответ на пункт 1: **НЕТ** — Госключ не умеет подписывать произвольный файл, загруженный вручную (например PDF, присланный Николаем по почте). Приложение подписывает только то, что пришло через интегрированный канал: банк, госорган, работодатель или ЭДО-оператор по API. План «просто открыть Госключ и подписать письмо от Николая» технически не работает как есть.

**Можно при условии**: провести документ через ЭДО-оператора со встроенной интеграцией с Госключом — подтверждено для Диадока. Но не проверено до конца, доступна ли эта связка самозанятому-одиночке без организации именно для НЭП (кончился шаговый бюджет захода) — это главный оставшийся риск. Ниже — текст пункта для NDA, порядок действий и черновик ответа Николаю: Госключ основной способ, сканы — явный запасной, как просили.

## 1. Госключ и произвольный документ — да/нет

**Нет.** Госключ работает только с документами, поступающими через защищённый канал от интегрированного сервиса — функции «загрузить свой файл с телефона/почты и подписать» нет. Источник вторичный (первоисточник gosuslugi.ru/600373/1 не отдал текст через WebFetch — портал вернул технический экран, не содержание услуги): astral.ru, дословно — «Подписание всегда инициируется внешним сервисом: банком, оператором, ФНС, работодателем, контрагентом. Самостоятельно загрузить произвольный файл из памяти телефона и подписать его в Госключе нельзя — приложение работает только с документами, поступающими через защищённый канал.» Косвенно подтверждается ещё двумя независимыми источниками (bitrix24.ru, support.kontur.ru) — везде описан только сценарий «сервис прислал документ → Госключ получил уведомление».

Что остаётся, если Илья хочет именно Госключ: провести документ через ЭДО-оператора с кнопкой «подписать через Госключ» — подтверждено для Диадока (support.kontur.ru/diadoc/79739): документ грузится в веб-версию Диадока → уходит в приложение Госключ на телефоне → подписывается там → возвращается в Диадок. Диадок подтверждённо принимает физлиц и самозанятых без ИП, приём и подпись для них бесплатны (diadoc.ru/articles/86176).

**Непроверенный риск**: найденное описание интеграции Диадок↔Госключ по формулировке ближе к сценарию «сотрудник организации с личным КЭП», а не однозначно к «самозанятый без организации подписывает НЭП». Не исключено, что Диадок предложит физлицу только свою собственную НЭП (без выхода в Госключ) либо потребует КЭП. Надёжно закрыть вопрос можно только практически: Илье самому один раз бесплатно завести аккаунт физлица в Диадоке и посмотреть, что реально предлагает интерфейс. СБИС в этом заходе отдельно не проверялся вовсе.

## 2. Что нужно контрагенту, чтобы принять и проверить подпись

Если пересылка обычным файлом: Николай получает подписанный файл + отдельный файл подписи (.sig/.p7s — оба обязательны для проверки) и проверяет на gosuslugi.ru/pgu/eds; регистрация в Госключе ему не нужна. Если через общий кабинет Диадока — проверка автоматическая внутри системы, но тогда нужен его аккаунт там (у No Logo, возможно, уже есть).

## 3. Диадок / СБИС по отдельности

Диадок: принимает физлицо/самозанятого без ИП, входящие и подпись физлица бесплатны, интеграция с Госключом подтверждена (детали для НЭП без организации — риск выше). СБИС: не проверялся в этом заходе, оставляю открытым пунктом.

## 4. Текст пункта для NDA (готов к вставке, рядом с 7.3, не заменяет его)

«7.3-1. Стороны признают, что электронный документ (в том числе настоящее Соглашение), подписанный со стороны Стороны 1 усиленной неквалифицированной электронной подписью (в том числе выпущенной и применённой через государственное мобильное приложение «Госключ»), а со стороны Стороны 2 — усиленной квалифицированной либо иной электронной подписью в соответствии с правилами применяемого Стороной 2 оператора электронного документооборота, признаётся равнозначным документу на бумажном носителе, подписанному собственноручной подписью соответствующей Стороны, в силу ч. 2 ст. 6 Федерального закона от 06.04.2011 № 63-ФЗ «Об электронной подписи». Проверка подлинности подписи осуществляется получающей Стороной доступными ей средствами: для подписи физического лица — сервисом проверки на портале Госуслуг (gosuslugi.ru/pgu/eds), для документов через оператора ЭДО — средствами такого оператора.»

## 5. Конфликт с 7.3 (сканы)

Не конфликтует — это два разных признанных способа подписания одного документа, не исключают друг друга. Если Госключ/ЭДО не сработает на практике, 7.3 остаётся рабочим запасным вариантом без правок.

## Порядок действий для Ильи

1. Завести бесплатный аккаунт физлица в Диадоке (5-10 минут).
2. Посмотреть, предлагает ли кабинет подписание через «Госключ» для обычной НЭП (не только КЭП организации). Если да — загрузить туда NDA и подписать так.
3. Скачать подписанный файл + файл подписи (.sig/.p7s), переслать Николаю почтой — либо пригласить его как контрагента в тот же Диадок.
4. Если Диадок потребует платный тариф или КЭП — не тратить время, вернуться к сканам (п. 7.3, работает уже сейчас бесплатно).

## Черновик ответа Николаю (готов как есть)

«Отдельного ЭДО вроде Диадока или СБИС у меня пока нет как своего сервиса, но я подпишу электронной подписью — это Госключ, бесплатное приложение от государства, подпись там юридически равнозначна обычной, я это прямо прописал в тексте документа. Заведу для этого аккаунт физлица в Диадоке (пара минут) и подпишу там через Госключ, а вам пришлю готовый подписанный файл — либо, если у вас уже есть свой Диадок, могу подписать прямо у вас в системе, дайте знать. Если для вас это неважно и удобнее по старинке — могу просто распечатать, подписать от руки и прислать скан, это тоже прописано в документе как равнозначное».

## Что осталось непроверенным / где риск

Главный риск: доступна ли связка «Диадок + Госключ + НЭП» физлицу-самозанятому без организации на практике — не проверено, снимается одной попыткой Ильи завести аккаунт. СБИС отдельно не проверялся вовсе. Первоисточник услуги на gosuslugi.ru/600373/1 не открылся через WebFetch — вывод о невозможности прямой загрузки файла основан на трёх независимых вторичных источниках, не на первоисточнике. Норма ст. 6 63-ФЗ повторно не сверялась — использована проверенная сегодня же в job-163.
