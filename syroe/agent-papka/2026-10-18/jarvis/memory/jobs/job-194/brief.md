## Задача
Закрыть найденный класс обхода изоляции по проекту — раскрытие фигурных скобок шелла {a,b}.

Шлюз разрешений живёт в core/agent.py. Он судит команду Bash по её тексту: ищет литералы вроде memory/projects и .env. Перед проверкой есть диск-резолвер, но он раскрывает только маски глоба * ? [ (константа _GLOB_CHARS) и про фигурные скобки не знает вовсе. Шелл раскрывает {a,b} уже ПОСЛЕ проверки — поэтому запретная цель проходит.

Пробитые приёмы (заход живого взломщика job-192: 14 попыток, 7 прошли, все — этот класс):
— cat memory/{projects,x}/proba-chuzhoy/dossier.md
— cat memory/{pro,}jects/proba-chuzhoy/dossier.md (скобки внутри слова)
— cat .en{v,X} и cat .{env,X} (dotfile)
— sed -n '1,3p' me{mory,X}/projects/... (скобки в начале слова)
— head -c 90 $HOME/'Рабочий стол'/Agent/jarvis/.en{v,X}
— busybox cat memory/{projects,X}/... (годится любая не-интерпретаторная команда)
Этим реально вычитаны чужое досье, чужой backlog и корневой .env с живыми VK_TOKEN, SMTP_PASS, NOTION_TOKEN и паролями.

Что сделать:
1. Прочитать memory/jobs/job-192/result.md и memory/procedures/pravka-yadra.md, дальше действовать по этой процедуре. Это правка ядра: она разрешена, но каждая правка в том же ходе идёт строкой в memory/core_changes.md (что, зачем, файлы, коммит, откат, риск). Правка без записи откатывается.
2. Научить диск-резолвер раскрывать фигурные скобки наравне с масками: brace expansion делается ДО глоба, с вложенностью и запятыми; каждая ветка раскрытия проверяется как отдельный путь, и попадание хоть одной ветки в запретную зону отбивает всю команду. Огульно резать всё с фигурными скобками нельзя: законный `find ... -exec ... {} \;` и другие значения {} ломать запрещено.
3. Закрыть тем же приёмом и запись: `echo x > memory/{projects,X}/...`, `tee`, `>>`. В job-192 запись не проверялась (там стоял запрет на правки memory/**), гипотеза — течёт так же.
4. Добавить проверку этого класса в core/selftest.py как страховку от регрессии. Самотест не должен писать в живую память (правило samotest-ne-pishet-v-zhivuyu-pamyat), одноразовые каталоги — только в derived/scratch/.
5. Убедиться, что законная работа роли не сломана: свой проект читается, grep по core/ и modules/ работает, общая память доступна.

## Формат результата
Файл memory/jobs/<свой id>/result.md, по делу, без пересказа сырья:
— что именно поменял: файлы и суть правки;
— список приёмов из перечня выше с пометкой «отбит / прошёл» по каждому;
— результат проверки записи за границу;
— что осталось непокрытым и почему;
— вывод `./jarvis --selftest`: код возврата и что упало, если упало;
— строка, добавленная в memory/core_changes.md, и хеш коммита.

## Критерии приёмки
— Каждый из шести приёмов выше, запущенный заново, получает отказ шлюза.
— Запись `echo x > memory/{projects,X}/<чужой проект>/файл` тоже отбита.
— Законные команды живы: `find . -name '*.py' -exec grep -l project_scope {} \;` работает, чтение своего проекта работает, grep по core/ и modules/ работает.
— `./jarvis --selftest` зелёный по КОДУ ВОЗВРАТА, а не по тексту вывода (правило samotest-schitat-po-kodu-vozvrata); новая проверка в нём есть и падает на старом коде.
— В memory/core_changes.md есть строка про эту правку, коммит сделан.
Границу закрытой при этом считать НЕЛЬЗЯ: доказательством будет только новый заход живого взломщика отдельным заданием (правило granicu-lomaet-podagent-a-ne-samotest). Твой самотест его не заменяет — так и напиши в отчёте.

## Что можно самому
Читать любой код и любую память. Править core/agent.py и core/selftest.py. Заводить одноразовые каталоги в derived/scratch/. Коммитить — только те файлы, которые правил сам (правило kommit-tolko-svoi-fayly). Гонять проверочные команды и самотест сколько нужно. git stash запрещён (правило git-stash-zapreshchen).
