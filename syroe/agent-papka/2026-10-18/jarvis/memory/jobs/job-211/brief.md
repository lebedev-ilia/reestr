## Задача
Собрать полный инвентарь всех файлов памяти агента и предложить черновой список из 15-20 тематических узлов, по которым эти файлы разложатся. Это вход для новой редакции схемы памяти; сама схема пишется отдельно и позже. НИЧЕГО НЕ ПЕРЕНОСИТЬ И НЕ ПРАВИТЬ в memory/** — только читать и описывать.

## Зачем (контекст, без него работа бессмысленна)
Сегодня оглавление памяти плоское: каждый файл — строка в системном промпте. Файлов 158, прирост 6-7 в сутки, строка в среднем 270 байт. Оглавление уже 42,6 КБ и режется. Решение Ильи: плоское оглавление заменяется тематическими узлами — в промпте 15-20 строк «тема, о чём она, сколько внутри файлов и байт, путь к карте темы», а карта темы это отдельный файл с полным списком и описаниями, который читается только когда пошёл в эту тему. Главный критерий качества тем: через год на вопрос «какое первое письмо мы отправили Николаю» агент за несколько шагов должен понять, где смотреть, и найти. То есть темы нарезаются под ПОИСК ответа, а не под красоту классификации.

## Где искать
- memory/facts/*.md (около 65 файлов), memory/procedures/*.md (около 30), memory/rules/*.md (около 50). У каждого файла есть шапка с id и заголовок первой строкой.
- MEMORY.md — действующая схема памяти, прочитать целиком ПЕРЕД работой.
- memory/facts/sborka-konteksta-ustroystvo.md — как файлы попадают в промпт.
- Даты: git log --follow --format=%ad --date=short -- <файл> | tail -1 даёт дату появления файла.

## Что сделать
1. Пройти все файлы в memory/facts, memory/procedures, memory/rules. Для каждого записать: путь, id, заголовок, размер в байтах, дату появления и дату последней правки, одну строку «о чём», список упомянутых сущностей (люди, компании, сервисы, документы: Николай Кочубеев, No Logo Studio, ВК, Notion, HH.ru, NDA и так далее), диапазон дат, о котором файл говорит, если он виден.
2. Предложить 15-20 тем. Для каждой темы: короткое имя, одна строка «о чём», список файлов, число файлов, суммарный объём в байтах, диапазон дат, ключевые сущности, 3-5 поисковых подсказок («первое письмо», «NDA», «оплата модели»). Тема, куда попало больше 25 файлов, обязана быть расписана на подтемы — формат должен быть деревом с самого начала.
3. Отдельно выписать файлы, которые не влезли ни в одну тему, и сказать честно почему.
4. Отдельно выписать кандидатов в карточки сущностей: человек, компания, документ, площадка — с перечислением, где про них уже лежат данные (файлы памяти, журналы вроде memory/outbox/sent.jsonl, каталоги drafts, threads).

## Что можно самому
Читать что угодно; писать только два файла: derived/pamyat-inventar.md (таблица по всем файлам) и derived/pamyat-temy-chernovik.md (список тем и карточек). Одноразовые скрипты — в derived/scratch/2026-09-02-inventar/.

## Формат результата
Два файла в derived/ (см. выше). В result.md — не больше 30 строк: перечень предложенных тем одной строкой каждая с числом файлов и байт, и три места, где классификация была спорной.

## Критерии приёмки
1. В инвентаре есть КАЖДЫЙ файл из трёх каталогов, число строк совпадает с числом файлов на диске (проверить командой ls | wc -l и сравнить).
2. Тем от 15 до 20, ни одна не пустая, суммарно они покрывают все файлы без остатка, кроме явно выписанных «не влезших».
3. У каждой темы указаны число файлов, байты, диапазон дат и поисковые подсказки.
4. git status показывает изменения только в derived/.
