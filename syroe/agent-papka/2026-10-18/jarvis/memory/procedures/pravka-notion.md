## Предусловия
NOTION_TOKEN в .env. Модуль modules/notion/write.py (запись разрешена Ильёй 23.08.2026). Свежий снимок derived/notion/raw.json + workspace.md — по нему ищутся кандидаты, чтобы не ходить в API вслепую. Для массовой заливки — разобранный источник (для лета это derived/vk_media/2026-08-23/250_ops.json, 371 операция из выписки) и явное «заливай» от Ильи.

## Шаги
1. Кандидатов искать ПО СНИМКУ, а не запросами: raw.json даёт полные id, родителей, last_edited_time, workspace.md — тексты. Id в отчётах обрезать нельзя: у Notion первые 8 знаков совпадают у половины объектов (общий префикс по времени создания), по ним объекты не различаются.
2. Перед архивированием дубля сравнить обе версии через api.call(/pages/id) + prop_text по всем свойствам и blocks_text. Дубль — только когда вторая версия не беднее. Пример: задачи Сони в Tasks и Календаре совпали слово в слово, но у календарной оказалось точнее поле даты (окно 21–25.08 против одной даты), поэтому убиралась версия из Tasks.
3. Проверка права записи одним безобидным действием: python -m jarvis.modules.notion.write создаёт черновик под Life os и сразу архивирует его.
4. Правки только через write.py: archive / unarchive / set_title / replace_in_page / create_page. Каждая пишет «как было» в memory/notion_writes.jsonl (с 24.08; раньше журнал лежал в derived/notion/ и мог погибнуть вместе с зоной). Откат — write.rollback(n).
5. Пустая строка в базе — не всегда мусор: у двух записей Finance не было названия, но были суммы и категории. Такие не архивировать, а именовать (set_title) или оставить и спросить.
6. После правок обновить факт notion-ustroystvo и сказать Илье, что именно ушло в корзину, с id и одной командой отката.

МАССОВАЯ ЗАЛИВКА (лето в Finance, job-035, 79 записей за один заход):
7. Сначала прочитать, что в базе УЖЕ есть, и только потом писать. Правило отсечки дубля, которое сработало: совпадение (дата + сумма без учёта знака). Всё, что совпало, — не заливать, а выписать поштучно.
8. Совпадения разобрать глазами, а не выкинуть скопом: после заливки нашлись 4 совпадающие пары, и все четыре оказались разными реальными операциями одного дня на одну сумму. Отсечка по (дата+сумма) — сито для проверки, а не приговор.
9. Спорное не заливать вовсе. Для лета из 371 операции исключены 46 спорных (12 вопросов Илье, факт vypiska-sber-leto-2026, раздел СПОРНОЕ) — они ждут его ответов, а не догадки.
10. Приёмка — ПЕРЕЧИТЫВАНИЕМ из Notion, а не по намерению кода: база 15 → 94 записи. Число «сколько собирался залить» доказательством не является.
11. Задание отдавать подагенту: заливка идёт ~13 минут и держать на ней главного нельзя. В брифе явно: согласие Ильи уже получено, спросить его подагент не может.

## Известные грабли
· Страницу верхнего уровня (parent = workspace) API архивировать НЕ может: 400 «Archiving workspace level pages via API not supported». Такие убирает Илья руками — предупреждать сразу, а не после попытки.
· Журнал пишется ДО действия, поэтому в нём остаются строки о неудавшихся правках; rollback должен пропускать ошибки и идти дальше (сделано).
· Правку текста делать по фрагментам rich_text, а не заменой блока целиком: иначе схлопнутся ссылки и оформление.
· Артефакты генерации в текстах Ильи выглядят как filecite…, обёрнутые невидимыми символами U+E200–U+E206; регулярка по ним, а не по слову.
· Пустые базы (Покос, Такси, Просмотры, Квартиры) — это незапущенный каркас, а не мусор. Не убирать: поиск квартиры стартует 27.08 (Илья перенёс с 25.08 решением 23.08), база пригодится.
· Notion не даёт «перенести» страницу в другого родителя на закреплённой версии API 2022-06-28.
· Заливка останавливается, если в базе уже лежит частично тот же период: 26.08 в Finance были 15 записей за 16–25.08, и первый заход был отменён именно из-за них — сначала правило отсечки, потом запись.
