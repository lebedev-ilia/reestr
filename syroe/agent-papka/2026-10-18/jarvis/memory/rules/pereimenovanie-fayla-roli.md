**Правило:** Не переименовывать рабочий файл, с которым живёт постоянная роль (очередь проекта, журнал, STATUS.md), пока роль работает. Понадобилось новое имя — либо делать это внутри задания самой роли, либо не трогать имя вовсе. Иначе роль на следующем заходе не найдёт файл по старому пути и создаст его заново: два файла с расходящимся содержимым, ни один не полный.
**Почему:** 30.08.2026: в 12:06, чиня запрет шлюза на имя backlog.md, я сделал git mv queue.md в backlog.md, чтобы имя совпало с документом Ильи. В 12:26 тимлид vnutrennii зашёл по расписанию, файла на месте не нашёл и создал queue.md заново. Полдня проект жил с раздвоенной очередью, критерий c-07 задачи t-002 был красным именно из-за этого, а в памяти закрепилось ложное «файл нельзя удалить никому». На деле запрет к тому моменту уже судил по пути и удалению не мешал.
**Как применять:** Перед git mv такого файла посмотреть, есть ли у роли расписание и когда следующий заход (папка роли в memory/agents). Либо провести переименование заданием роли, либо оставить имя как есть, а расхождение с документом описать словами в самом файле.
