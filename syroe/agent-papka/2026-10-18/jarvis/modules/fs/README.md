# fs — поиск по файлам ПК

Владелец: агент. Добавлен 24.08.2026 по решению Ильи о полном доступе к машине
(факт `pc-dostup-ustroystvo`). Отвечает на вопрос «где лежит файл с таким
именем» и «где вообще что лежит и сколько весит».

Индексируются **только имена и метаданные**: путь, каталог, имя, расширение,
размер, время изменения. Содержимое файлов не читается ни при сборке, ни при
поиске — во всём модуле нет ни одного `open()`, и самотест это проверяет,
подменяя `builtins.open` взрывающейся заглушкой на время сборки.

## Команды

    cd "…/Agent"
    jarvis/.venv/bin/python -m jarvis.modules.fs.index build     # полная пересборка
    jarvis/.venv/bin/python -m jarvis.modules.fs.index update    # только изменившееся
    jarvis/.venv/bin/python -m jarvis.modules.fs.index stat      # что в индексе
    jarvis/.venv/bin/python -m jarvis.modules.fs.index tree      # карта каталогов
    jarvis/.venv/bin/python -m jarvis.modules.fs.index search отчет --ext pdf

Руками звать `update` не нужно: его раз в сутки делает ночной цикл вместе с
дневной свёрткой (`core/night.py::fs_index_update`), а числа кладёт в лог
строкой `night_fs_index`. Свежесть базы видна командой `stat`.

Поиск: `--sub` (подстрока где угодно в имени), `--dir ПУТЬ`, `--ext pdf,docx`,
`--min 10M`, `--max 1G`, `--newer 7d|2026-01-01`, `--older`, `--kind f|d`,
`--secret`, `--sort mtime|size|name|path`, `--limit`.
Без `--sub` ищется по началу слов имени (быстро, доли миллисекунды); если так
ничего не нашлось, подстрока пробуется сама.

Карта: `tree --depth 2 --top 8` — дерево с числом файлов и объёмом узла,
единицы килобайт, помещается в контекст целиком.

## Что где

- `scan.py` — границы обхода, списки шума, метка личного. Три списка, их нельзя
  путать: `HARD_PRUNE` (точные пути ядра), `NOISE_DIRS` (имена кэшей и
  окружений на любой глубине), `SECRET_*` (не отсев, а метка).
- `index.py` — схема, сборка, инкремент, поиск, карта, CLI.
- `selftest.py` — проверки на дереве-образце в `derived/scratch/`. Входит в
  `./jarvis --selftest`.

База: `derived/fs/index.db`. Живёт в производной зоне законно — возвращается
одной командой `build` (правило `v-derived-tolko-vosstanovimoe`).

## Границы

Корни берутся из `/proc/self/mounts`: системный раздел и всё, что Илья
смонтировал (второй диск, флешки). Виртуальные ФС, снапы и слои докера
отсекаются по типу ФС, а не по списку путей — новый снап не потребует правки
кода. Точка монтирования диска живёт в `/run/media/...`, поэтому `/run`
отсекается точным совпадением пути, а не префиксом.

Отсев — по содержимому, а не по важности: Илья сказал «в индекс включать всё
без исключений», и личные каталоги под отсев не попадают. Виртуальные окружения
ловятся маркером `pyvenv.cfg`, а не именем: зовут их как угодно.

## Личное

`.ssh`, `.gnupg`, `.env`, `*.pem`, `*.key`, профили браузеров помечаются
столбцом `secret`. Путь и имя в индексе есть — иначе не ответить «где лежит
ключ». Выдача помечает такие строки знаком `!` и приписывает, что содержимое не
открывать. Никакая команда модуля содержимое и не откроет.

## Чего модуль не делает

- Не ищет по содержимому файлов — Илья это отложил.
- `update` не замечает правку файла на месте без смены имени: он опирается на
  mtime каталога, а тот от записи в существующий файл не меняется. Для «где
  лежит» это неважно; «что менялось» — задача журнала изменений (fanotify),
  он ещё не сделан.
- Не следит за файлами в реальном времени. Индекс отстаёт ровно на время с
  последнего `update`; проверить «прямо сейчас» — `find`/`rg`, полный обход
  занимает секунды.
