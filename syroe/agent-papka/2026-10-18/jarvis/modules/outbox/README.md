# Исходящая почта и сообщения (outbox)

Чтение списка контактов, вычитка перед рассылкой, в перспективе — отправка.
Владелец — агент.

## Что уже умеет

- `contacts.py` — разбор markdown-карточек (`### N.M Название` + поля `- Ключ:`)
  в структуру: контакт, каналы связи, готовое письмо. Плюс аудит: общие ящики,
  дубликаты адресов, карточки без канала, telegram-боты и каналы вместо людей.
- `checkdns.py` — MX-проверка доменов. Домен без MX = гарантированный bounce,
  а каждый bounce портит репутацию отправляющего ящика.

- `send.py` — отправка по SMTP с журналом. Три предохранителя: без `--send`
  печатаются только черновики, за запуск не больше `--limit` писем (по умолчанию 3),
  адрес из журнала `memory/outbox/sent.jsonl` пропускается всегда.
- `subjects.json` — тема письма на каждую из 60 карточек. Тем ровно 60, каждая
  30–55 символов, привязана к зацепке конкретной карточки. Карточка без темы
  не отправляется.
- `funnel.py` — **воронка**: `derived/logs/funnel.md`, строка на партию, на каркас
  (T1-T4) и на сегмент — контактов / писем / дошло / ответили / отлупы / молчат /
  «рано». Числа только из журналов; связка «письмо ↔ ответ» берётся у `history`,
  своей второй не заводится. Единица счёта — контакт, а не письмо. Отклик
  считается от дошедших, без отлупов. Ручные письма и продолжения переписки
  (второе письмо тому же домену без карточки) в воронку не идут — иначе один
  клиент даёт два «ответил».
  ```
  python3 -m modules.outbox.funnel            # пересобрать
  python3 -m modules.outbox.funnel --print    # и напечатать
  python3 -m modules.outbox.funnel --json     # машинный вывод
  ```
- `followup.py` — **второе касание**: `derived/logs/followup.md`, черновик
  догоняющего письма каждому, кто молчит дольше 6 суток с ПОСЛЕДНЕГО ушедшего
  письма. Кандидатов и статусы берёт у `funnel`, тексты — из каркасов `F1`
  (пара к T1) и `F4` (пара к T4), тему — из журнала отправки, чтобы письмо
  село в тот же тред по теме. Отправки в модуле нет вовсе: тексты уходят Илье
  черновиком, без его «да» ничего не уходит. Когда «да» будет — отправлять
  придётся отдельным путём: третий предохранитель `send.py` пропускает любой
  адрес, уже лежащий в журнале, и вдогонку через него письмо не уйдёт.
  ```
  python3 -m modules.outbox.followup           # пересобрать
  python3 -m modules.outbox.followup --print   # и напечатать
  python3 -m modules.outbox.followup --days 4  # другой порог, разово
  ```
- `history.py` — досье на каждый контакт в `derived/threads/`: шапка (компания,
  карточка, каркас, источник) и хронология «→ отправлено / ← ответ» из двух
  журналов, `sent.jsonl` и `replies.jsonl`. Плюс сводка `INDEX.md`. Пилоты не
  в счёт. Зона производная: каталог сносится и пересобирается одной командой,
  результат побайтово тот же.

```
python -m jarvis.modules.outbox.contacts [файл.md] [--json]
python -m jarvis.modules.outbox.checkdns [файл.md]
python -m jarvis.modules.outbox.send [файл.md]            # черновики, ничего не уходит
python -m jarvis.modules.outbox.send --send --limit 3     # отправка, не больше трёх
python -m jarvis.modules.outbox.send --send --pilot me@x  # пилот: письма на свой ящик
```

История переписки (запускается из корня агента):

```
python3 -m modules.outbox.history                          # пересобрать все досье
python3 -m modules.outbox.history --contact hi@example.ru  # одно досье
```

## Вторая волна и планировщик (wave2/)

`wave2/` — отдельный пул на 340+ карточек (`send_wave.py` вместо `send.py`
напрямую) и планировщик ежедневной порции: 15 писем в сутки, каждое в 07:00
МЕСТНОГО времени города адресата. Подробности — `wave2/README.md`.

## Грабли

Регулярка на email вида `[\w-]+\.[a-z]{2,}` молча обрезает трёхуровневые домены:
`info@alfaline.spb.ru` превращался в `info@alfaline.spb`. Поймалось только
MX-проверкой — глазами такой адрес выглядит правдоподобно. Домен матчить как
`(?:[\w-]+\.)+[a-zA-Z]{2,}`.

Ключ поля бывает с уточнением в скобках: `- Письмо (в комментарии к статье): …`.
Резать ключ по `(`, иначе три карточки раздела 3 остаются «без письма».
