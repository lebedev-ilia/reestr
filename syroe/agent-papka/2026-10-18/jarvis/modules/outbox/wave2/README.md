# modules/outbox/wave2/

Здесь живут карточки контактов ВТОРОЙ волны рассылки Alverra (сверх первых 60 из
T-835_60_KONTAKTOV.md). Владелец — агент, задача от Ильи 24.08.2026: довести пул
до 400 контактов и 400 писем. Разрешение на отправку пула целиком дано 25.08.2026
(«письма хорошие, рассылай по 15 в день») — процедура memory/procedures/
ezhednevnaya-rassylka-15.md.

- `BRIEF.md` — общий бриф для агентов-сборщиков. Читается перед любой партией.
- `<сегмент>-<партия>.json` — результат одной партии: карточки (тема и тело письма
  лежат прямо в карточке, включая поле `city` — нужно планировщику).
- `dupcheck.py` — доля своего текста по каждой партии (штампы считаются по всему
  пулу, не по партии). Порог приёмки в отправку — 38%+, задаёт процедура, не код.
- `status.py` — **приёмка всех партий одной командой**: validate + dupcheck +
  журнал отправленного сведены в одну таблицу, строка на партию, вердикт словом
  (БРАК / ДОРАБОТАТЬ / ГОТОВА / ОТПРАВЛЕНА). Это то, чем заменяется ручной круг
  «поправил файл — прогнал validate — прогнал dupcheck — нашёл глазами свою
  строку» (за 25.08 круг повторён больше полутора сотен раз, bl-080). Буквы в
  аргументах — фильтр ПОКАЗА: разбор всегда идёт по всему пулу. Код возврата 1,
  если среди показанных есть БРАК.
  ```
  python3 -m modules.outbox.wave2.status              # таблица по всем партиям
  python3 -m modules.outbox.wave2.status --details    # + что именно чинить
  python3 -m modules.outbox.wave2.status AH AG        # показать эти партии
  python3 -m modules.outbox.wave2.status --json       # машинный вывод
  ```
- `send_wave.py` — переходник партии в формат `send.py`: сама отправка, журнал
  (`memory/outbox/sent.jsonl`) и три предохранителя — только там, второй дороги
  наружу нет.
- `geo.py` — город карточки → смещение от UTC (все 89 городов пула на 25.08.2026,
  Россия часовые пояса не переключает с 2014 года). Неопознанный город получает
  Москву +3 с явной пометкой `resolved=False`.
- `planner.py` — планировщик ежедневной порции: 15 писем в сутки, каждое — в
  07:00 МЕСТНОГО времени города адресата (не Владивостока, не Москвы). Тикает
  вместе с демоном ВК (`modules/vk/daemon.py`), по образцу `core/night.py`.
  Состояние — `derived/outbox_plan.json` (план дня, восстановимо из wave2/*.json
  + dupcheck + журнала). Стартует с 26.08.2026, суточная квота считается по
  факту отправленного в журнале, а не по плану. Подробности и грабли — в шапке
  файла. Ручные команды (из каталога НАД jarvis):
  ```
  jarvis/.venv/bin/python -m jarvis.modules.outbox.wave2.planner plan            # план дня, сухой прогон
  jarvis/.venv/bin/python -m jarvis.modules.outbox.wave2.planner plan --rebuild  # форсировать пересбор плана
  jarvis/.venv/bin/python -m jarvis.modules.outbox.wave2.planner tick            # сухой прогон тика
  jarvis/.venv/bin/python -m jarvis.modules.outbox.wave2.planner tick --send     # тик по-настоящему (письма уходят)
  ```
- `planner_selftest.py` — самотест планировщика (календарь, окно допуска,
  квота, оркестрация тика на заглушках) — часть `./jarvis --selftest`, ни одного
  настоящего письма не шлёт.
- Сведения партий в `../letters.json` / `../subjects.json` НЕ будет (bl-044 снята
  26.08). Тема, тело и каркас письма второй волны живут в самой карточке партии,
  и это единственный их дом: `send_wave.to_send_format` отдаёт их в `send.run`,
  `history.py` читает партии напрямую. Второй файл с теми же текстами разошёлся
  бы с правками Ильи в партиях и однажды отправил бы человеку старую версию.
  `letters.json`/`subjects.json` остаются домом первой волны (60 карточек T-835).

Письма от имени Ильи по-прежнему подчиняются правилу `ot-imeni-ili-cherez-
chernovik`, но для уже согласованного каркаса этой рассылки исключение прямо
в самом правиле: список адресатов и темы показываются, черновик на каждое
письмо — нет (разрешение 25.08 дано на пул целиком, а не на письмо).
