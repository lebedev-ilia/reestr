# modules/vk — канал связи через сообщество ВК

Владелец: Илья. Добавлено: 2026-08-22. Статус: experimental, испытательный срок до 29.08.2026.

Зачем: общаться с агентом не из терминала. Тот же `agent.turn()`, та же память,
другой вход.

Запуск: `./jarvis --vk`

## Что нужно от Ильи (5 минут, один раз)

1. **Создать сообщество**: vk.com/groups → «Создать сообщество» → любой тип.
2. **Включить сообщения**: Управление → Сообщения → «Сообщения сообщества: включены».
3. **Разрешить боту работать**: Управление → Сообщения → Настройки для бота →
   «Возможности ботов: включены».
4. **Long Poll**: Управление → Работа с API → Long Poll API → включить,
   версия **5.199**; вкладка «Типы событий» → отметить **Входящее сообщение**.
5. **Токен**: Управление → Работа с API → Ключи доступа → создать ключ
   с правом **«Сообщения сообщества»**.
6. **Свой id**: открыть vk.com/id... в адресной строке, либо просто написать
   боту — демон напечатает в консоль `впиши VK_OWNER_ID=...`.

Дальше — `cp .env.example .env` в корне агента и вписать три значения
(`.env` в гит не попадает, `.gitignore` его знает):

```
VK_TOKEN=vk1.a....      # ключ доступа сообщества, права: сообщения
VK_GROUP_ID=123456789   # id сообщества (число из адреса club123456789)
VK_OWNER_ID=12345       # id Ильи; отвечаем только ему
```

Пока `VK_OWNER_ID` не задан, агент не отвечает никому — только печатает id
написавшего. Это намеренно: чужой человек не должен получить доступ к памяти.

## Отступление от контракта модулей

`modules/README.md` требует `tool.py` с чистыми функциями. Здесь этого нет:
канал связи — не инструмент агента, а точка входа в него, и под контракт
инструментов он не ложится. Отмечено намеренно, а не по недосмотру.

## Известная дыра: подтверждения

`core/agent.make_guard` спрашивает разрешение через `input()` — то есть в
терминал. У демона терминала нет, вопрос повис бы навсегда. Поэтому ход из ВК
идёт с `unattended=True`: действия «средней цены» отклоняются, быстрый путь
отключён (каждый ход длинный).

Правильное лечение — дать `turn()` принимать способ спрашивать, чтобы вопрос
уходил в тот же чат. Это правка ядра, ядро правит Илья. Предложение отправлено
22.08.2026.

## Как доставляется ответ

Правило Ильи от 22.08: голосом то, что укладывается в минуту, остальное текстом.

- порог — 1000 знаков (замерено: Piper даёт ~20 знаков речи в секунду);
- текстом уходит и то, что слушать бессмысленно: код, ссылки, таблицы;
- переопределение — первой строкой ответа `[голосом]` или `[текстом]`;
  метка снимается и в чат не попадает;
- сбой озвучки (нет модели, ВК не принял документ) откатывается в текст.
  Потерять ответ хуже, чем прислать его не тем способом.

## Промежуточные статусы

Ход бывает долгим. «Печатает» показывает, что процесс жив, но не что делается —
Илья просил видеть, над чем идёт работа:

```
cd "<каталог выше корня агента>" && jarvis/.venv/bin/python \
    -m jarvis.modules.vk.notify "смотрю код канала"
```

Запускать именно оттуда, иначе пакет `jarvis` не находится. Ошибки статуса
не роняют ход — статус вещь вспомогательная.

## Чего пока нет

- своего распознавания голосовых: используется только расшифровка, которую
  сделал сам ВК (асинхронная, иногда не приходит);
- микрофона и динамиков на этом компьютере.

Всё это — отдельная способность, отдельный протокол, отдельное решение Ильи.

## Файлы

- `api.py` — транспорт VK API, без зависимостей, только `urllib`
- `daemon.py` — цикл long-poll, разбор сообщения, вызов агента, доставка ответа
- `notify.py` — промежуточный статус в чат из середины хода
- `selftest.py` — прогон цикла на подменённом API, без сети и токена

Состояние (`derived/vk.json`) — производное: позиция в очереди событий и id
последнего обработанного сообщения по каждому собеседнику. Сносится безболезненно.

## Проверка без ВК

```
./.venv/bin/python -m jarvis.modules.vk.selftest
```

Подменяет `api.call`, `api.poll`, `agent.turn` и синтез речи, прогоняет через
цикл двенадцать событий и проверяет: дедупликацию (повтор того же сообщения не
даёт второго хода), фильтр чужих, коды `failed` 1/2/3, отложенную расшифровку
голосового, отказ ВК расшифровать (не ждём зря), событие в старом формате,
нарезку длинного ответа, отказ ВК принять ответ, выбор голос/текст, метку
`[текстом]` и откат в текст при сбое озвучки. Печатает `OK`.

Прогонять после любой правки `daemon.py` — иначе поломка обнаружится в чате
и будет выглядеть как «агент молчит».

## Что сверено с документацией, а что нет

Самопроверка проверяет логику цикла, но не то, что ВК действительно так
отвечает. 22.08 сверено отдельно (`dev.vk.com` недоступен из-под агента,
источник — референсные библиотеки `vk_api`, `vk-io`):

- **сверено:** коды `failed` 1/2/3 и реакция на каждый; вложенный
  `object.message` в событии `message_new`; коды ошибок отправки
  (7, 9, 901, 914) — обрабатываются с внятной подсказкой в консоль;
- **не сверено:** поля `transcript` / `transcript_state` у `audio_message`.
  В официальной схеме ВК их нет — они существуют, но недокументированы.
  Поэтому расшифровка голосовых считается ненадёжной по построению, и своё
  распознавание понадобится не «для красоты», а чтобы канал вообще работал
  с голосом.

Отдельно заложена страховка: если Long Poll настроен на версию младше 5.103,
сообщение приходит прямо в `object`, без вложенного `message`. Такое событие
не теряется, но в консоль уходит просьба поставить 5.199.
