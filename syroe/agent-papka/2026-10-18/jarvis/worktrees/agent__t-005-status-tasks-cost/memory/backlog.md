# Очередь собственных задач

Чем агент занимается, когда Илья молчит. Верхняя строка по приоритету берётся
фоновым ходом (core.agent.self_cycle). Приоритет: меньше — раньше.
Статусы: open | wip | blocked | done | dropped | sleep:ГГГГ-ММ-ДД. «Циклов» —
сколько фоновых ходов съедено; три без завершения опускают задачу вниз очереди.

sleep:ДАТА — ежедневное дело, сделанное на сегодня: разбор входящих,
пересборка истории переписки, дневная порция писем. done для такого — ложь,
а wip держит его в очереди до полуночи, и фоновый ход берёт его снова через
десять минут после прогона (27.08: два хода подряд на bl-054, второй дубль
первого). Очередь не видит задачу до названного дня, а с его наступлением
берёт как обычную. Ставится тем же вызовом:
core.memory.backlog_update('bl-NNN', status='sleep:2026-08-28', checkpoint=...).

blocked — задача ждёт не меня, а Илью или внешнее событие. Очередь её не берёт.
Условие называется машиночитаемо, ссылкой ob-NNN в чекпоинте: закроется
обязательство — задача сама вернётся в open перед следующим фоновым ходом.
blocked без ссылки на ob не разблокирует никто; такие попадают в лог строкой
`backlog_blocked_forever`.

Сюда попадает только то, что имеет нулевую цену ошибки и делается внутри своей
папки. Всё, что требует Ильи, живёт в memory/obligations.md, а не здесь.

ТАБЛИЦУ РУКАМИ НЕ ПРАВИТЬ. Статус, чекпоинт, циклы, приоритет — только через
core.memory.backlog_update(id, status=..., checkpoint=..., bump_cycle=True);
новая задача — backlog_add(what, why, prio); текст вокруг таблицы —
backlog_intro_set(text). Правка питоном, sed'ом или перезапись файла
отбиваются шлюзом (core.agent.backlog_direct_write): семь колонок сбиваются
молча, а поля читаются кодом по номеру — съехавшая строка означает потерянную
или самовольно вернувшуюся задачу. Edit по файлу очереди отбит целиком.
