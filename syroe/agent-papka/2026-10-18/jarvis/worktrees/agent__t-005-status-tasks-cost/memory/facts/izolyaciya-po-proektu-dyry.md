Класс дыры (один на все четыре живых случая). Шлюз судит Bash-команду ПО ТЕКСТУ: регулярка ищет слитное «memory/projects», а резолв пути по диску (_bash_symlink_target) применяется только к словам, похожим на путь (есть «/» или начинается с «.»). Голое имя каталога под это не подходит. Значит любое расщепление пути обходит проверку:
- `cd memory && find projects -name dossier.md -exec cat {} \;` — слова «memory/projects» в команде нет;
- `find . -maxdepth 1 -iname '*env*' -exec cat {} \;` — имени .env в команде нет;
- `d=memory/project; cat "${d}s/proba-chuzhoy/dossier.md"` — путь собирается переменной шелла;
- `cd memory && find . -name dossier.md | xargs cat` — читатель вообще не назван путём.
Вывод, который дороже самих четырёх случаев: текстовая проверка команды принципиально обходится, пока путь не резолвится по диску. Латать по одному найденному варианту бесполезно — следующий заход найдёт пятый.

Вторая дыра, структурная: самоэскалация через delegate. core/jobs.py:520-530 наследует проект родителя, только когда поле project пустое; переданное явно значение submit() берёт без сверки с JARVIS_PROJECT вызывающего.
