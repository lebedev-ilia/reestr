# Оценка доли площади отходов и заполненности (п. 6 ТЗ, задача 2)

Проверка гипотезы: класс `waste` не поддаётся детекции (mAP@0,5:0,95 = 0,725, и никакие приёмы
не помогли), но, возможно, **долю площади** по нему оценить можно — а ТЗ (п. 6) требует именно
«сегментацию контейнера и содержимого, вычисление доли заполнения», а не детекцию отходов.

**Методика оценки взята из практики** оценки площадей по сегментации: там применяют не IoU/mAP,
а **абсолютную ошибку доли**, **отношение предсказанной площади к истинной** и **корреляцию**.
Это принципиально: mAP измеряет совпадение каждого объекта, а для площади важна суммарная
величина, где ошибки на отдельных объектах частично компенсируют друг друга.

Данные: сегментационный датасет `dumpster` (622 валидационных изображения, 6 классов,
полигональная разметка CVAT). Классы содержимого: `tko`, `treewaste`, `constrwaste`, `tires`.
Контейнер: `dumpster`. Модель: YOLO11n-seg, обученная ранее (mask mAP@0,5 = 0,493).

| Метрика | Значение |
|---|---|
| Изображений | 622 |
| Средняя истинная доля | 4,71 % |
| Средняя предсказанная | 4,49 % |
| **Средняя абсолютная ошибка (MAE)** | **1,06 п.п.** |
| Медианная абсолютная ошибка | **0,26 п.п.** |
| **Отношение площадей** (предсказано / истина) | **0,954** |
| Ошибка в пределах 5 п.п. | **96,3 %** изображений |
| Ошибка в пределах 10 п.п. | **98,2 %** |
| **Корреляция** предсказания и истины | **0,911** |
| **Тривиальный прогноз** (средняя доля по выборке) | 4,57 п.п. |
| MAE там, где отходы действительно есть (394 кадра) | 1,30 п.п. |
| Отношение площадей там, где отходы есть | 0,909 |

**Главный вывод: модель в 4,3 раза точнее тривиального прогноза** (1,06 п.п. против 4,57 п.п.),
хотя её mAP как сегментации — всего 0,493. То есть **для оценки площади модель пригодна,
даже когда по метрикам сегментации выглядит слабой.**

**Что честно сказать про точность:** абсолютная ошибка 1,06 п.п. при средней доле 4,71 %
означает **относительную ошибку около 22 %**. Абсолютная цифра выглядит отлично только потому,
что отходы занимают малую часть кадра. Для практики это надо формулировать так:
«оценка доли площади — с точностью порядка единиц процентных пунктов», а не «22 % от значения».

**Систематическое смещение:** отношение площадей 0,954 (0,909 там, где отходы есть) —
модель **недооценивает** площадь примерно на 5–9 %. Это смещение можно скомпенсировать
калибровочным коэффициентом — стандартный приём при оценке площадей и объёмов.

## 3. Доля заполнения (содержимое / контейнер) — НЕ РАБОТАЕТ, и вот почему

| Метрика | Значение |
|---|---|
| Кадров, где доля вычислима | 557 |
| **Кадров, где истинная доля БОЛЬШЕ 1,0** | **111 (20 %)** |
| Кадров, где больше 2,0 | 61 (11 %) |
| Максимум отношения | **67,9** |
| Кадров с физически осмысленной долей (≤ 1,0) | 446 (80 %) |

**Ключевая проблема: у 20 % кадров «содержимого» по площади больше, чем «контейнера».**
Это не ошибка модели — это свойство **разметки**: полигоны содержимого и контейнеров никак
не связаны между собой. В кадре может быть несколько контейнеров и кучи отходов рядом с ними;
отношение «вся площадь отходов в кадре / вся площадь контейнеров в кадре» **не является
заполненностью** и может превышать единицу физически невозможным образом.

Даже на оставшихся 80 % физически осмысленных кадров результат слабый:

| Метрика (446 кадров) | Значение |
|---|---|
| MAE | 10,4 п.п. |
| В пределах 10 п.п. | 81 % |
| В пределах 20 п.п. | 88 % |
| **Корреляция** | **0,456** |
| Средняя истинная доля | 0,22 |
| Средняя предсказанная | 0,26 |

**Корреляция 0,456 — это слабая связь.** То есть заполненность в текущей постановке
не оценивается надёжно, и дело не в модели: контейнер оценивается с точностью 99,2 %,
содержимое — с ошибкой 1,35 п.п. Проблема в **отсутствии связи между ними в разметке**.

## 3.4. ВАЖНОЕ УТОЧНЕНИЕ: в датасете `waste_up` связь «содержимое ↔ контейнер» ЕСТЬ

**Исправление прежнего вывода.** В разделе 3 сделан вывод, что связь содержимого с контейнером
в разметке отсутствует. Этот вывод **относится к датасету `dumpster`** (классы `tko`,
`treewaste`, `constrwaste`, `dumpster`) и **неверен для `waste_up`**. Проверка показала:

| Проверка (датасет `waste_up`, 434 кадра с отходами) | Результат |
|---|---|
| Кадров, где вместе с отходами есть машина | **434 (100 %)** |
| Объектов `waste`, центр которых лежит внутри рамки машины | **446 из 446 (100 %)** |
| Отходы перекрывают кузов более чем наполовину | 442 (99,1 %) |
| Отходы перекрывают кузов более чем на 80 % | 427 (95,7 %) |

**Что это значит.** В `waste_up` класс `waste` — это **отходы в кузове машины**, а не куча
на земле. То есть «контейнер» и «содержимое» в разметке уже связаны геометрически, и **задача 2
ТЗ решается на существующих данных без всякой переразметки**.

### Заполненность кузова — прямой ответ на задачу 2

Формула: `заполненность = площадь отходов внутри кузова / площадь кузова`.

Проверено на 434 кадрах, где есть и отходы, и машина (модель — текущая YOLO11n, порог 0,25):

| Метрика | Значение |
|---|---|
| Средняя истинная заполненность | 34,9 % |
| Средняя предсказанная | 35,4 % |
| **Средняя абсолютная ошибка** | **6,98 п.п.** |
| Медианная ошибка | **2,61 п.п.** |
| **Отношение площадей** | **1,014** — систематического смещения нет |
| Ошибка ≤ 5 п.п. | 65,7 % кадров |
| Ошибка ≤ 10 п.п. | 79,7 % кадров |
| **Корреляция** | **0,715** |
| Тривиальный прогноз (средняя заполненность) | 10,26 п.п. |
| Фактический диапазон заполненности | **8–86 %** |

**Модель в 1,5 раза точнее тривиального прогноза**, и — что важнее — диапазон измеряемой
величины реальный (от 8 до 86 %), а не доли процента. Это осмысленная прикладная величина:
она отвечает на вопрос «насколько полно загружена машина».

### Сравнение двух подходов к задаче 2

| Подход | MAE | Корреляция | Что измеряет |
|---|---|---|---|
| Заполненность кузова (раздел 3.4) | 6,98 п.п. | 0,715 | **насколько полон кузов — прямая формулировка ТЗ** |
| Доля площади в зоне (раздел 3.5) | 1,78 п.п. | 0,886 | сколько отходов находится в рабочей зоне камеры |

Меньшая абсолютная ошибка у зонального подхода объясняется тем, что там и значения малы
(в среднем 7,8 %), поэтому и ошибка в процентных пунктах меньше. **По смыслу задаче 2
соответствует заполненность кузова**, а зональная доля — полезная дополнительная метрика
(например, для контроля замусоренности площадки).

## 3.5. Вариант 3 (зона вместо контейнера) — тоже работает, проверено на данных Заказчика

**Ограничение, заданное Заказчиком: переразметки не будет.** Поэтому варианты 1 и 2 отпадают,
и остаётся только вариант 3. Он проверен на датасете `waste_up` (1061 изображение, 8 камер)
с уже построенными полигональными масками.

**Формулировка:** доля заполнения = площадь объектов класса `waste` **внутри зоны** / площадь зоны.

| Метрика | Значение |
|---|---|

| Средняя истинная доля | 7,79 % |
| Средняя предсказанная | 7,82 % |
| **Средняя абсолютная ошибка** | **1,78 п.п.** |
| Медианная ошибка | 0,0 п.п. |
| **Отношение площадей** (предсказано / истина) | **1,004** |
| Ошибка ≤ 2 п.п. | **85,9 %** изображений |
| Ошибка ≤ 5 п.п. | **92,8 %** |
| **Корреляция** | **0,886** |
| **Тривиальный прогноз** (средняя доля по выборке) | 9,36 п.п. |
| Кадров, где отходы есть в зоне | 434 |
| MAE на этих кадрах | 4,20 п.п. |

**Что это даёт:**
- **Модель в 5,3 раза точнее тривиального прогноза** (1,78 против 9,36 п.п.).
- **Отношение площадей 1,004 — систематического смещения нет**, в отличие от варианта
  с сегментацией (там было 0,954, то есть недооценка на 5 %). Зона убирает смещение.
- **Корреляция 0,886** — связь сильная.

**Ограничение, которое надо назвать честно:** в датасете `waste_up` разметка **в боксах, а не
в полигонах**, поэтому «площадь» здесь — площадь рамок, а не реального силуэта отходов.
Она завышает настоящую площадь. Но так как истина и предсказание считаются по одному правилу,
измеренная точность осмысленна: она показывает, **насколько точно модель воспроизводит
размеченную площадь**. Физическая площадь отходов по этим данным неизвестна.

### Проверка качества самой зоны (алгоритм маски)

Документированная практика требует проверять зону измеримым критерием, а не «на глаз».
Проверено: какая доля размеченных объектов попадает внутрь зоны своей камеры.

| Показатель | Значение |
|---|---|
| Проверено объектов | 1552 |
| **Внутри зоны** | **1504 (96,9 %)** |
| Вне зоны | 48 (3,1 %) |

Зона покрывает практически всю активность — она не отсекает полезные детекции.

**Чтобы задача 2 (п. 6) стала решаемой, нужен один из вариантов — выбор за Заказчиком:**

1. **Связать содержимое с контейнером в разметке** — полигон отходов должен относиться
   к конкретному контейнеру. Тогда доля заполнения станет корректной величиной.
   Самый точный вариант, но требует переразметки.
2. **Разметить заполненность напрямую** — например, категориями (пусто / до половины / полно)
   или процентом. Тогда задача становится классификацией, и её можно решить без связи полигонов.
   Обычно самый дешёвый по разметке путь.
3. **Задать фиксированную зону** (полигональная маска, уже реализована в этапе 1) и считать
   долю заполнения как **площадь отходов внутри зоны** относительно площади самой зоны.
   Тогда связь с контейнером не нужна вовсе — зона и есть контейнер.
   **Этот вариант не требует новой разметки и может быть выполнен на имеющихся данных.**

**Рекомендация: вариант 3 — и он уже проверен (раздел 3.5).** Переразметка не требуется,
результат получен на данных Заказчика, зона покрывает 96,9 % объектов. Метрика —
«доля площади зоны, занятая отходами»: измерима, устойчива, проверяема.

## 5. Оговорки

1. **Оценка проведена на датасете `dumpster`**, а не на `waste_up`: полигональная разметка
   отходов есть только там. Переносить цифры на боевые камеры `waste_up` напрямую нельзя —
   там размечались боксы, а не полигоны.
2. **Использована существующая модель сегментации** (обучена 60 эпох, mask mAP@0,5 = 0,493).
   Модель не дообучалась под площадь — и тем показательнее результат: она уже даёт 0,911
   по корреляции.
3. **Смещение 5–9 %** не скомпенсировано; при внедрении нужен калибровочный коэффициент,
   рассчитанный на отложенной выборке.
4. **Заполненность не проверена на боевых данных** — только на этом датасете, где связь
   содержимого и контейнера отсутствует.
