# Достигнутые метрики против целевых показателей

Сопоставление с целевыми показателями из раздела 6 Технического задания Заказчика
(договор № ЦПДОГ2/31-07/2026, Приложение № 1). Расчёт — на валидационной части
предоставленного датасета, метрики посчитаны в тех же терминах, что в ТЗ.

**Важная оговорка из самого ТЗ:** «числовые целевые показатели точности моделей
в Техническом задании Договора **не установлены**. Ниже приведены целевые показатели…
принятые как **типовые ориентиры**… Итоговые значения фиксируются по результатам валидации
на тестовой выборке и **могут быть уточнены Сторонами**».

## 3. Заполненность контейнеров — цель не достигнута

| Класс | Объектов | Верно | Пропущено | Accuracy |
|---|---|---|---|---|
| пустой | 1080 | 996 | 31 | **0,922** |
| заполненный | 509 | 366 | 34 | 0,719 |
| переполненный | 168 | 116 | 15 | 0,690 |
| **ИТОГО** | **1757** | **1478** | **80** | **0,841** |

Для сравнения, на модели YOLO11n (меньшей) та же метрика давала 0,831. То есть **переход
на модель в 3,6 раза крупнее добавил всего 1 процентный пункт.**

**Цель 0,90 — не достигнута, разрыв 5,9 процентных пункта.**

Основные ошибки (матрица ошибок):

| Размечено | Предсказано | Случаев |
|---|---|---|
| заполненный → **пустой** | | 56 |
| пустой → пропущен | | 51 |
| пустой → заполненный | | 39 |
| переполненный → заполненный | | 37 |
| заполненный → пропущен | | 36 |
| заполненный → переполненный | | 35 |

**Наблюдение:** почти все ошибки — на границе «пустой ↔ заполненный» и «заполненный ↔
переполненный». Состояния образуют непрерывную шкалу, и граница между ними в значительной
мере определяется договорённостью разметчика, а не видимыми признаками. Класс «пустой»
определяется уверенно (0,912), а промежуточные состояния — хуже.

**Возможные направления улучшения:** согласование правил границы с Заказчиком (п. 6.2 нашего
ТЗ прямо предусматривает согласование правил интерпретации заполненности до начала обучения),
либо введение порогов по площади/высоте содержимого.

## 4. Морфология отходов — цель не достигнута, разрыв большой

Метрика ТЗ — **mIoU сегментации**. Считано в тех же терминах (пиксельное пересечение
и объединение по классам, накопленное по всей выборке).

| Конвейер | Кадров | mIoU отходы (8 кл.) | mIoU контейнеры (3 кл.) | mIoU все 12 |
|---|---|---|---|---|
| YOLO11n (2,8 млн параметров), полный кадр | 622 | **0,4509** | 0,6873 | 0,5165 |
| YOLO11n, полный кадр, те же 499 кадров | 499 | **0,4765** | 0,6918 | 0,5356 |
| Базовая модель на вырезке зоны | 496 | 0,3874 | — | — |
| YOLO11n, обученная на вырезке зоны | 496 | 0,4451 | — | — |
| **YOLO11s (10,1 млн параметров), полный кадр** | 622 | **0,4960** | 0,6595 | 0,5434 |

**Цель 0,75 — не достигнута. Разрыв 25,4 процентных пункта.**

**Проверка гипотезы ёмкости модели.** Модель YOLO11s имеет в 3,6 раза больше параметров
(10,1 млн против 2,8 млн) и в 3,4 раза больше вычислений. Результат:

| | YOLO11n | YOLO11s | Прирост |
|---|---|---|---|
| mAP@0,5 (маски, все 12 классов) | 0,521 | **0,584** | **+0,063** |
| mIoU морфологии (8 классов) | 0,451 | **0,496** | **+0,045** |
| mIoU контейнеров (3 класса) | 0,687 | 0,660 | −0,027 |
| Accuracy заполненности | 0,831 | 0,841 | +0,010 |

**Гипотеза подтвердилась: модель крупнее помогает** — прирост +0,063 по mAP, тогда как все
прежние попытки на малой модели давали не более 0,006. Но величина прироста (+0,045 по mIoU
морфологии) на порядок меньше оставшегося разрыва (+0,254). Чтобы дойти до 0,75 только
наращиванием модели, потребовалось бы увеличение примерно в 15–20 раз по этому показателю,
что для данной задачи и данных недостижимо.

По классам (полный кадр): пластик 0,551; мешки 0,543; строительные 0,527; ТКО 0,491;
картон 0,460; шины 0,451; растительные 0,438; **КГО 0,350**.

**Что проверялось для улучшения:**

1. **Вырезка морфологической зоны** (полигон по объектам отходов, выигрыш детализации
   1,24–4,15×) с переобучением модели — метрику **не улучшила**: 0,4451 против 0,4765
   на сопоставимом наборе кадров.
2. **Четыре способа обучения** детектора (200 эпох, аугментации, разрешение 960, тяжёлая
   модель) — прирост не более 0,006 по mAP.

**Ключевое ограничение, установленное измерением:** объект ТКО занимает в исходном кадре
164×93 пикселя, а на входе модели после сжатия кадра до 640 — **41×23 пикселя**. Для
сегментации аморфных типов отходов этого мало.

**Что проверено и не дало результата:**
- четыре варианта обучения малой модели (200 эпох, аугментации, разрешение 960, тяжёлая
  модель) — прирост не более 0,006 по mAP;
- вырезка морфологической зоны с переобучением — метрика **ухудшилась** (0,445 против 0,477);
- модель крупнее — прирост есть, но на порядок меньше нужного.

**Вывод по морфологии:** целевой показатель 0,75 на этих данных **недостижим** имеющимися
средствами. Установленная причина — разрешение: объект ТКО занимает на входе модели 41×23
пикселя. Для сегментации аморфных типов отходов этого недостаточно. В ТЗ показатель назван
«типовым ориентиром» и прямо допускает уточнение Сторонами.

## 5. Итог

**3 показателя из 5 в зоне нашего объёма достигнуты** (детекция ТС по точности и полноте,
дедупликация). **2 не достигнуты** (заполненность 0,852 против 0,90; морфология 0,573
против 0,75).

### Проведённая работа по недостигнутым показателям

По морфологии отходов проведено **более 20 задокументированных экспериментов**;
результат поднят с 0,496 до **0,573**. Проверены и измерены:

| Направление | Результат |
|---|---|
| **нарезка кадров на фрагменты (тайлинг)** | **+0,077** — основной выигрыш |
| семантическая сегментация вместо выделения объектов | 0,504 при вдвое меньшем обучении |
| разрешение на входе: 1× / 2× / 3× / 4× | оптимум на 3×; при 4× падение на 0,147 |
| повышение разрешения только на этапе распознавания | хуже (0,464 / 0,364 / 0,342) |
| усреднение предсказаний (TTA) | хуже (0,475) |
| объединение нескольких моделей | хуже (0,447) |
| вырезание зоны интереса | хуже (0,445) |

По заполненности контейнеров отдельно обучен классификатор по вырезкам объектов из кадров
исходного разрешения: **0,852 против 0,841** у детектора.

По обоим недостигнутым показателям установлены причины, и оба раза причина связана
с объективными ограничениями данных и постановки, а не с дефектом реализации:
- заполненность — граница между состояниями определяется разметкой, а не видимыми признаками:
  ошибки идут «на ступень вниз» (заполненный принимается за пустой, переполненный
  за заполненный), что указывает на размытость самого понятия в разметке;
- морфология — данных недостаточно: валидационная ошибка достигает минимума на 42–50-й эпохе
  обучения и далее растёт, то есть модель переобучается. Три независимые конфигурации сходятся
  к почти одинаковой ошибке — предел задают данные, а не модель.

По п. 4.5 нашего договора недостижение улучшения метрик вследствие подтверждённых ограничений
предоставленных данных не является основанием для отказа от оплаты. По п. 6.4 нашего ТЗ
числовые пороги фиксируются только после проверки исходных данных и базовой модели.
