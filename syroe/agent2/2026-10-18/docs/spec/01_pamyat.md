## 4. Поиск (Вопрос 42)

Четыре шага:

| Шаг | Что делает | Время |
|---|---|---|
| 1 | параллельно FTS5/BM25 + `sqlite-vec`, топ-M = 40 | ~100–200 мс |
| 2 | слияние **RRF k=60** | ~10 мс |
| 3 | composite scoring | ~50–100 мс |
| 4 | ACL-gated возврат топ-N 5–10 | ~10 мс |

- Веса: `search 0.50 / recency 0.25 / confidence 0.25`; для recency-намерения — `0.10 / 0.70 / 0.20`.
- Half-life по типам записей: decision / hub / antipattern — **бесконечно**; project — 120 дней;
  research — 90; note — 60; progress — 45; handoff — 30.
- Cross-encoder: capped 300, **scope-aware: память НИКОГДА не реранжируется** (−10.5 п.п. при обратном).
- Confidence: три исхода — `PASS / FLAG / FILTER`.
- Метрики: top-5 > 90 %, ранжирование 2.6 мс (N=200), RRF < 10 мс, cross-encoder < 50 мс,
  ACL violations 0, budget utilization 60–80 %, retrieval 59.5 % против sliding window 7.7 %,
  Recall@10 > 78.4 %, VAIL — −84 % отказов. Из Вопроса 3: search latency **< 200 мс**,
  index freshness **< 1 с** для свежих записей.

## 5. Консолидация и ротация

- **Write-time** (при каждой записи): дедупликация точных совпадений token-Jaccard ≥ 0.95;
  similarity > 0.85 → LLM-план `keep/update/delete`; при недоступности модели — graceful degradation.
- **Reconciliation** (на старте): не более 20 пар; reinforce +0.05; contradict → supersede +0.1; weaken −0.1.
- **Sleep cycle**: триггер — 100+ записей, завершение проекта или раз в сутки; операции
  merge / supersede / synthesize (при 3+ независимых записях) / prune.
- **TTL по типам**: episodic 30–90 дней (в Вопросе 3 было 45 — сдвиг); semantic 6–12 месяцев
  (в Вопросе 3: `importance < 2` и `access_count = 0` за 90 дней); procedural — иммунитет;
  policy — никогда.
- Utility score: Ebbinghaus `R(t) = e^(−t/S)`, half-life 29 дней; тиры Active / Warm / Cold / Archived
  (0.7 / 0.5 / 0.3); heat = `read_count × 0.9^age_weeks`; soft-archive; **Forget Log** (8 полей)
  в неизменяемом журнале.
- **Никогда не удаляется**: policy, procedural (иммунитет), constitutional invariants (Вопрос 109),
  decision / hub / antipattern (half-life бесконечный).

## 6. Когерентность и провенанс

- Session consistency + **lazy invalidation** (95 % экономии токенов при V=0.05) + Write-CAS +
  typed conflict (`stale_write` / `lost_update` / `stale_correction`) + различение
  «рассказанная запись» и «подтверждённая запись».
- Четыре режима отказа (Margalit) и четыре примитива; VAIL: **«retrieval authorizes inspection, not use»**.
- Ссылки на практику: StateFuse / MemTX / LatticeMind 0.97 / MELD 30/30; CRDT `version_vector` +
  `logical_clock`; trust-weighted с LWW-фолбэком.
- Провенанс: W3C PROV-DM, provenance DAG TD(λ), BPMA bitemporal + principal, Causal Seal,
  TRACE (90 % атрибуции, 2^−256), false-corroboration `n_eff = k/(1+(k−1)·φ̄)`,
  weakest-link `effective_confidence = min(declared, chain.min_confidence)`.
- Метрики: traceability 100 %, AuditEval 100 %.

## 7. Аудит и доступ

- Hash-chain SHA-256, append-only; **Merkle** (RFC 6962, MMR: блок 1000 событий, 14 операций SHA-256,
  эпоха < 1 мс); witness countersignatures; Run Capsule (15 сущностей + DsSE + RFC 3161);
  **две оси времени** (`valid_time` + `transaction_time`); **content не пишется — только hash**;
  content-optional (hashed-only / content-included); read audit; authorization audit; 5 инвариантов KRINEIA.
- Доступ: derivation-gated (производная запись наследует классификацию не ниже максимальной
  из источников, источники перепроверяются при каждом чтении); AKAC `decide()`;
  MemLineage RFC-6962 + Ed25519; hard gate **до** ранжирования; fail-closed; namespace RBAC;
  AES-256-GCM + per-tenant keys (CNSA 2.0) + TLS 1.3; embeddings шифруются.
- Обязательные поля записи аудита в журнале **явно не перечислены**; есть только ACR
  (`correction_id`, `prior_record`, `reason`, `trigger`, `fix_type`, `corrected_content`,
  `source_type`, подпись Ed25519/JCS, hash_chain) — стр. 3655–3667.

## 11. Противоречия и решения

**Решено пользователем 2026-10-13:** (1) схема записи — **минимум 12 полей**, остальные
опционально; (2) сроки хранения — **разные по типу записи**; (3) при конфликте «иммунитет
против права на забвение» — **иммунитет политик и процедур сильнее**, персональные данные
клиентов удаляются полностью. Следствие: поле `memory_type` обязательно с самого начала.
