## Где остановились

Идёт **исследование методов улучшения морфологии отходов без объединения классов**
(просьба пользователя). Найдена и подтверждена причина слабости — **разрешение**:
детектор видит объект ТКО как 41×23 px.

## Что уже сделано по этому исследованию

1. **Изучены источники:** CLIP/Tip-Adapter для отходов (Fraunhofer), двухступенчатая
   классификация, иерархическая классификация, ArcFace.
2. **Проверена гипотеза разрешения** — подтверждена: классификатор на вырезке 224×224 получает
   в 7,8 раза больше деталей.
3. **Обучен классификатор на вырезках** (15 458 / 2 774): точность **0,77**, ТКО **0,844**,
   КГО **0,621** — против 0,445 и 0,220 у детектора.
4. **Сквозная оценка дала прирост всего +0,005.** Причина установлена: **узкое место — полнота
   детектора** (пропускает 58–73 % объектов), а не классификация.

## Расследование ЗАВЕРШЕНО — результат отрицательный, но содержательный

**Двухступенчатая схема не даёт выигрыша в сквозной метрике** (проверены три варианта
при двух порогах; измеритель проверен контролем 0,995).

| Схема | mAP@0,5 при 0,25 | при 0,05 |
|---|---|---|
| Одна ступень | **0,370** | **0,423** |
| Две ступени (12 кл.) | 0,376 | 0,286 |
| Две ступени (отходы=1) | 0,354 | 0,277 |

При этом по отдельности обе части лучше: детектор «отходы одним классом» даёт **0,760 против
0,569**, классификатор типа — **79–84 % против 22–45 %**. Выигрыш не переносится, потому что
mAP критичен к ранжированию по уверенности, а класс и уверенность берутся у разных моделей.

**Полезный побочный результат:** детектор с одним классом отходов существенно лучше находит
отходы — это готовое улучшение для подсчёта и контроля наличия.

**Объединять классы не потребовалось.**

## Важные предупреждения для продолжения

- **Классы сопоставлять ТОЛЬКО по именам, никогда по номерам** — на этом я ошибся дважды.
- **Проверять строку `Scanning ...` в логе обучения** — она показывает, какие метки реально читаются.
- **Не делать символических ссылок на КАТАЛОГИ данных** — ultralytics разыменует их и берёт
  метки не оттуда.
- **`cv2.dnn.NMSBoxes` не знает о классах** — для детекции использовать класс-зависимый NMS.
