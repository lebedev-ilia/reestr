## 2. Главный пробел: baseline-модели нет

Проверено поиском по всему серверу и по Mac:

- `find /home /opt /srv /data -name '*.pt' -o -name '*.onnx' -o -name '*.engine' -o -name '*.pth' -o -name '*.weights'` → **пусто**.
- На Mac в `Downloads` лежат только **общие предобученные** веса YOLO (`yolo11n/s/m/l.pt`) — это не модели заказчика.
- `python3 -c "import torch"` → **`ModuleNotFoundError: No module named 'torch'`** (Python 3.12.3, ML-стека нет).
  Ultralytics, torchvision, ONNX/TensorRT — тоже не установлены.
- Telegram с сервера недоступен (`api.telegram.org` → `000`), но **google и pypi открыты (200)** → пакеты поставить можно.

**Вывод:** «базовая модель», с которой по ТЗ сравнивается новая, сейчас недостижима: ни весов, ни обученной модели на инфраструктуре нет, ML-окружение не развёрнуто. По ТЗ базовые модели предоставляет Заказчик — значит либо они на Jetson'ах в офисе («включить некому»), либо не переданы.

## 4. Метрики baseline (что считаем)

По трём задачам ТЗ:

| Задача ТЗ | Метрика | Как считаем |
|---|---|---|
| Детекция ТС в полигональной зоне | **mAP@0.5 и mAP@0.5:0.95**, Precision/Recall, F1 | стандартный COCO-протокол (pycocotools) на фиксированной val-выборке |
| Дедупликация ТС | **доля повторных фиксаций** (duplicate rate) и **снижение ложных срабатываний** | на последовательностях кадров одной камеры: сколько раз одно ТС зафиксировано повторно |
| Заполненность/морфология отходов (МН, ТКО, КГО) | **IoU / Dice** по полигональной маске, **MAE** по оценке заполненности, accuracy классов морфологии | сравнение предсказанной маски с GT CVAT |
| Адаптация под Jetson Nano 4 ГБ | **FPS, latency (мс), пик VRAM (МБ), размер весов** | прогон на целевом железе; ограничение 4 ГБ — жёсткое |

Дополнительно фиксируем условия: разрешение входа, камера (Cam1 и др.), погода/свет/ракурс — по ТЗ
ограничения данных должны попасть в отчёт.

## 5. Порядок работ до получения baseline

1. **Уточнить у Заказчика (Сергей Редькин, @rs385) происхождение «базовой модели»** — блокирующий вопрос.
   Без неё «сравнение базовой и новой модели» по приёмке невозможно. Заодно спросить про доступ к Jetson.
2. **Развернуть ML-окружение на сервере** (pip с pypi работает): torch (CUDA 13 под RTX 5080 —
   проверить совместимость сборок), ultralytics, pycocotools, onnxruntime/TensorRT для Jetson-экспорта.
3. **Сформировать фиксированную val-выборку** из размеченных задач CVAT (`cvat_share.zip` локально +
   бэкапы задач на сервере), зафиксировать её состав хешами — по ТЗ тестовая выборка фиксируется Заказчиком.
4. **Обучить/взять собственный baseline** (YOLO11 как отправная точка), посчитать метрики из п. 4 —
   это даёт числовой ориентир, даже если модель заказчика так и не появится.
5. **Отдельно проверить дедупликацию** на последовательностях кадров (алгоритм трекинга + правило
   «одно ТС — одна фиксация в зоне»).
6. **Зафиксировать пороги по FPS/метрикам только после п. 1–4** — по ТЗ числовые пороги
   определяются после проверки данных и базовой модели.

## 6. Риски

- **Нет baseline** → приёмка «сопоставимо с базовой» не закрывается. Риск договорной, не технический.
- **Jetson Nano 4 ГБ** — жёсткий лимит памяти; модель придётся сильно квантовать/ужимать.
  Проверять можно только на целевом железе, а оно в офисе.
- **Канал связи с заказчиком** — Telegram с сервера недоступен (блокировка), переписка идёт только с Mac.
- **Отсутствие ML-стека** — решается, но это часы работы и подбор версий torch под CUDA 13.
