## 3. Техническая разведка: как вообще получить заказы FL.ru

| Проверка | Команда/инструмент | Результат |
|---|---|---|
| Публичный API | поиск + проба эндпоинтов | **API нет**; парсинг только по HTML |
| Список заказов | `curl https://www.fl.ru/projects/` | HTTP 200, 393 КБ — карточки отдаются сервером, без авторизации |
| Структура карточки | разбор HTML | есть `data-disposable-project-id`, заголовок, бюджет, превью описания, время |
| Категории | разбор ссылок | 15 нужных категорий вида `/projects/category/<slug>/` |
| Пагинация | пробы `page-N` | работает; конец пагинации отдаёт 404 (это не сбой) |
| Страница заказа | `curl` карточки 5525247 | HTTP 200: **полное ТЗ**, бюджет, возраст аккаунта заказчика, его отзывы, JSON-LD schema.org |
| Число откликов | поиск в HTML | **анонимно не отдаётся** (только под аккаунтом) — заменено на возраст аккаунта и отзывы |
| Статус заказа | поиск строки «выбрал исполнителя» | работает: позволяет отсеять уже занятые заказы |

## 4. Что сделано по шагам

1. **`fl_parser.py`** — сбор заказов из 15 категорий (по 6 страниц).
   Результат: **877 заказов** в [`fl_orders.json`](fl_orders.json), 14 «ошибок» — это конец пагинации.
2. **`fl_rank.py`** — скоринг по профилю: 7 групп ключевых слов с весами, негативный фильтр
   (SEO, дизайн, копирайт, найм, инженерия, 1С-консалтинг и т. п.), бонусы за бюджет.
   Результат: 409 прошли фильтр, 90 в первом шортлисте.
3. **`fl_details.py`** — догрузка детальных страниц: полное ТЗ из JSON-LD, цена, дата публикации,
   возраст аккаунта заказчика, отзывы, рейтинг. Результат: 234 карточки (кэш — `fl_cache/detail/`).
4. **Проверка статуса** — по кэшу найдено **55 занятых** заказов («Заказчик выбрал исполнителя»),
   осталось **179 активных** ([`fl_status.json`](fl_status.json), [`fl_active_all.json`](fl_active_all.json)).
5. **`fl_final.py`** — оценка «выполнимости»: конкретика ТЗ, бюджет, профиль заказчика, штрафы за
   партнёрские схемы и найм.
6. **`fl_top30.py`** — ручной отбор 30 заказов с уровнями A/B/C, разбором «почему берём / чем
   выделяемся / риски / что нужно от пользователя» → [`fl_top30.md`](fl_top30.md), [`fl_top30.json`](fl_top30.json).

## 5. Ошибки и тупики (зафиксировано честно)

| Ошибка | Причина | Как исправлено |
|---|---|---|
| В карточках не было числа откликов и полного ТЗ | парсер читал только список, а отклики публично не отдаются | добавлена догрузка детальных страниц; отклики заменены косвенными признаками |
| Первый прогон отчёта дал 24 и 26 позиций вместо 30 | часть отобранных заказов уже была занята, часть id не попала в активный пул | введена проверка статуса и подстановка равноценных активных заказов |
| Ошибка `fl_top30.py`: `NameError: out is not defined` | при правке файла через Python-скрипт потерялся блок инициализации | файл перезаписан целиком через инструмент `write`/`edit`, прогон повторён |
| Дубликаты id в списке отбора | ручная правка списка | добавлена защита `seen`, финальная проверка на дубли (0) |

## 8. Продолжение задачи (2026-10-13, по запросу «напиши текста для всех 30»)

**Что сделано:** написаны тексты откликов на все 30 заказов из [`fl_top30.md`](fl_top30.md).

| Шаг | Инструмент | Результат |
|---|---|---|
| Тексты откликов под каждое ТЗ | [`fl_otkliki.py`](fl_otkliki.py) | [`fl_otkliki.md`](fl_otkliki.md) — 30 текстов, [`fl_otkliki.json`](fl_otkliki.json) — данные |
| Проверка качества текстов | скрипт-валидатор | в каждом есть цена с «₽» и минимум один вопрос по существу; длина 1 252-2 539 знаков |
| Сводная таблица «цена + срок» | тот же скрипт | добавлена в шапку `fl_otkliki.md` |

**Принципы, по которым писались тексты:**
- никаких «готов выполнить, пишите в личку»: каждый текст — конкретный план (что именно делаю),
  результат, цена, срок и 2-3 вопроса по существу ТЗ;
- цена не выдумана: где заказчик объявил бюджет, отклик равен бюджету; где «по договорённости» —
  сумма с обоснованием и вариант урезанного объёма;
- риски названы прямо: у RVC — «8 минут исходников это нижняя граница», у эмуляции Ozon — серая
  зона по правилам сервиса, у 1С — «опыта сеньора нет, но отчёт сделаю и сверю с вашей выгрузкой»,
  у Laravel-проекта — «не наш основной стек, два варианта на выбор»;
- в каждом тексте есть хотя бы один вопрос — это фильтрует нецелевых заказчиков и показывает,
  что ТЗ прочитано, а не скопирован шаблон.

**Ограничения, которые честно зафиксированы в шапке `fl_otkliki.md`:**
- отправляет пользователь (доступа к аккаунту FL.ru у агента нет);
- не отправлять все 30 сразу: FL.ru ограничивает частоту откликов, разумный темп — 5-8 в день;
- перед отправкой проверять карточку на статус «Заказчик выбрал исполнителя».

**Итог по деньгам:** если возьмут всё — около 1,9 млн ₽ и загрузка на 4-6 месяцев.
Реалистичный старт: 3-5 заказов уровня A/B (≈150-250 тыс. ₽).
