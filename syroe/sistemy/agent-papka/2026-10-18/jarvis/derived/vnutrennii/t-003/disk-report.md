## c-03: сходимость с 162 ГБ (круг 2: пересчёт с docker system df)

Полный разбор первого уровня `/` (все каталоги, не только кандидаты, сумма из
таблицы выше): **114 212,97 МБ (111,54 ГБ)** — число из захода 1, повторно не
переснимал (круг 2 просит только добавить строку docker и пересчитать формулу).

Отдельная строка, требуемая кругом 2 — **неучтено du без root, путь
недоступен, оценка через docker demon**: `/var/lib/docker` (Images + Containers
+ Local Volumes + Build Cache). Эта строка НЕ кандидат в c-02/c-04 (внутрь
пути не заглянуть без root, содержимое непроверяемо через `test -e` на
конкретные файлы) — только числовой довесок для формулы c-03.

Число перепроверено заново в этом заходе (31.08 утром), не переписано со
слов инструкции: `docker system df` на этой же машине сейчас даёт Images
35,17 ГБ + Containers 0,1892 ГБ + Local Volumes 5,737 ГБ + Build Cache
16,74 ГБ = **57,8362 ГБ** (у docker сами ГБ уже десятичные, ×1000 в МБ, не
×1024) = **57 836,2 МБ**. Это чуть меньше значения из инструкции (58,73 ГБ) —
дневная разница объясняется тем, что докер-кэш и volumes меняются от часа к
часу (контейнеры пересобираются, build cache чистится), а не ошибкой счёта;
дельта в пределах 1 ГБ на пул в 58 ГБ не влияет на вывод.

Формула круга 2: `abs((du_sum_mb + docker_mb) - 162*1024) / (162*1024)`
= `abs((114212.97 + 57836.2) - 165888) / 165888`
= `abs(172049.17 - 165888) / 165888`
= `6161.17 / 165888`
= **0,0371** (3,71%).

**Порог 0,15 пройден** (3,71% < 15%, даже лучше ориентира из инструкции —
там ожидалось ~4,25% при значении 58,73 ГБ). c-03 закрыт.

Ниже — расчёт захода 1 оставлен для истории (что было ДО учёта docker, порог
не проходил):

Формула захода 1: `abs(sum(items_mb) - 162*1024) / (162*1024)`
= `abs(114212.97 - 165888) / 165888`
= `51675.03 / 165888`
= **0,3116** (31,16%, порог не пройден).

Пишу честно, куда делись недостающие ~50,5 ГБ до пересчёта: du не смог
прочитать `/var/lib/docker` (`Permission denied`, доказано командой
`du -x --max-depth=1 / 2>&1 1>/dev/null | grep docker`), а на этом
пути Docker хранит образы, volumes и build cache. Прямой запрос
`docker system df` (не через файловую систему, через демон — sudo не
задействован) даёт по этой же машине: 35,15 + 0,165 + 6,678 + 16,74 = 58,73 ГБ
номинально. С поправкой на то, что образы и build cache у Docker частично
делят общие слои (не считаются дважды на диске), 58,73 ГБ номинала против
50,46 ГБ недостачи — расхождение 8,27 ГБ в пределах ожидаемого от дедупликации
слоёв. Вывод: почти вся пропажа объясняется одним каталогом, доступным только
root, а не ошибкой счёта или тем, что диск «незаметно потёк» за время работы.
