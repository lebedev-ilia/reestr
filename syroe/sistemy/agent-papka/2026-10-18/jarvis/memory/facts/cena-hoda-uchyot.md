## Как устроено

SDK кладёт в `ResultMessage.total_cost_usd` НАКОПЛЕННОЕ сессией, а не цену
хода: внутри сессии ряд монотонно растёт и обнуляется только с новой сессией.
Соседние ходы приходят с одним `session_id`, поэтому наивная сумма по логу
складывает одно и то же по многу раз.

С 25.08.2026 в записи лога `{"result": ...}` лежит:
- `cost_usd` — цена ИМЕННО этого хода (прирост к прошлой записи той же сессии);
- `cumulative` — накопленное сессией, как его назвал SDK;
- `session` — id сессии;
- `turns` — число шагов модели.

Прошлое значение поднимается из лога (`core/agent.py`, `cost_delta` и
`_cost_prev_from_log`): процесс между ходами не живёт, а сессия живёт.
Считать цену суток — `modules/audit/daily.py`, функция `day_cost`; она же
печатается строкой «цена суток» в самоаудите.

Разложить расход по видам ходов — `modules/audit/spend.py` (bl-063, 26.08):
`python3 -m modules.audit.spend [ОТ [ДО]]` даёт по дням и за период ходы,
шаги, минуты и цену ОТДЕЛЬНО для ВК, фона и подагентов. Как он опознаёт ход:
`message_in` открывает ход и несёт актора (`ilya` / `self` / `job`), запись
`self` с `result` закрывает, поле `turn` связывает их точно. Вид берётся по
актору, а не по каналу: подагент ходит с `channel=self` и от фонового хода
каналом неотличим. Цена подагента лежит в логе дважды — в его собственной
записи `result` и в `job_done`; складывать надо только первую.

## Чего числа не значат

- Записи ДО 25.08.2026 держат в `cost_usd` накопленное. Их сумма врёт кратно:
  за 25.08 наивно выходило 1767 долларов при 135 накопленных, за 24.08 — 492.
  Восстановление по скачкам ряда даёт 243 и 172 — это ОЦЕНКА СВЕРХУ, а не
  счёт: рядом работали подагенты своими сессиями, и ряды в логе перемешаны.
  Точной цены за дни до 25.08 не будет никогда, называть её не надо.
- Доллары в логе вообще ничего не значат для Ильи: оплата по подписке Max,
  ограничение — токены и лимиты, а не деньги (правило `model-ne-ekonomit`).
  Числа нужны мне для сравнения ходов между собой — «этот ход вышел вдесятеро
  дороже обычного», — а не для отчёта о тратах.
- Цена задания подагента берётся из `LAST_RESULT` (`modules/jobs/run.py`) и
  теперь тоже прирост, а не итог сессии.
