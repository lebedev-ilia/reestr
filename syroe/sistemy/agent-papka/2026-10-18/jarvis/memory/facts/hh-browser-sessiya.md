24.08.2026 выполнен вход в аккаунт Ильи на hh.ru через Playwright (persistent context Chromium) — по прямой просьбе Ильи «логинься в hh, придёт новый код». Вход по email+одноразовый код (пароля к HH нет, это нормально — см. факт hh-ru-dostup, вход у hh только так).

Профиль браузера с куками активной сессии лежит в derived/hh_profile (~16 МБ).
С 26.08 путь именно такой: раньше профиль лежал в derived/scratch/, а эта зона по
правилам сносится не глядя как одноразовая — переезд в отдельный каталог сделан,
чтобы чистка scratch не убивала живую сессию (bl-051). Восстановим в любой момент повторным входом (см. процедуру vhod-hh-cherez-pochtu), поэтому нахождение в derived корректно, несмотря на то что содержит сессионные куки.

Это разовый ручной вход, не канал автоматизации hh: после логина ничего больше на сайте не делалось (не открывались вакансии, не листались резюме) — соглашение hh запрещает роботов (п.8.8 из hh-ru-dostup), риск блокировки реален. Расширять использование этой сессии (парсинг, отклики) без отдельного решения Ильи не стоит.
