Быстрое исследование 23.08.2026 (8 поисков + первоисточники Anthropic и Letta).

Что делают другие:
* Letta/MemGPT — память как ОС: «ядро» всегда в контексте (как RAM), остальное подгружается; агент сам редактирует свои блоки памяти. Плюс sleep-time compute (letta.com/blog/sleep-time-compute, github letta-ai/sleep-time-compute): в простое отдельный фоновый агент переписывает память основного — вычисления переносятся из момента ответа в паузу.
* Zep/Graphiti — темпоральный граф: у факта есть период валидности, новый факт закрывает старый, а не сосуществует с ним. Заявленно лучший результат на LongMemEval среди сравниваемых.
* Mem0 — самый массовый, ставка на дешёвое извлечение (единицы тысяч токенов на обращение вместо десятков).
* A-MEM (arxiv 2502.12110) — Zettelkasten: каждая запись = заметка с тегами, контекстом и ССЫЛКАМИ на соседей, при добавлении обновляются старые заметки. Заявлено кратное улучшение на многошаговых вопросах и −85..93% токенов на операциях памяти.
* Anthropic (effective-context-engineering-for-ai-agents, effective-harnesses-for-long-running-agents): compaction, внешние файлы-заметки, подагенты с чистым контекстом, just-in-time — держать в контексте идентификаторы и пути, а содержимое подгружать. Для долгих задач: файл прогресса + git-история как способ восстановить состояние, одна задача за сессию, обязательная самопроверка.

Главные выводы, применимые к файловой памяти под git:
1. Чисто векторный RAG как память ломается на противоречиях во времени (классический пример: «переехал в Мадрид», а агент советует рестораны в прежнем городе). Лечится не эмбеддингами, а полями валидности у факта.
2. Продакшн composes: полнотекст + структура + связи, а не одна технология. Гибрид FTS5(BM25) + вектор со слиянием RRF — стандартная дешёвая связка, работает на CPU (sqlite-vec).
3. Графовые базы дороги на обновлении: пересчёт индекса при каждом добавлении, устаревание не видно в логах ошибок. Для одного человека — избыточно.
4. Для русского обязательна лемматизация при индексации, иначе морфология съедает половину попаданий. Лёгкая модель под CPU — multilingual-e5-small (118M), для русского валидна (ruMTEB, arxiv 2408.12503).

Чего не нашёл: сравнений именно файловых markdown-памятей под git; все бенчмарки — про диалоговые истории.
