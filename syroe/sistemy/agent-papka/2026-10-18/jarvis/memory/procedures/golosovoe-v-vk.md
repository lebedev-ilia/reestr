## Предусловия
Канал ВК поднят (.env с VK_TOKEN/VK_GROUP_ID/VK_OWNER_ID). Голос скачан в derived/voices/. Пакеты piper-tts, soundfile, soxr в .venv. Голос по умолчанию — ruslan (выбран Ильёй 22.08 из трёх проб).

## Шаги
1. `from jarvis.modules.voice import say`
2. `ogg = say.synthesize(text, voice)` — внутри Piper даёт wav 22050, дальше ресемпл до 48000 и запись в ogg/opus.
3. `say.send_voice(token, group_id, peer_id, ogg)` — три шага ВК: адрес загрузчика, multipart-заливка, docs.save, messages.send с вложением.
4. Проверка руками: `./.venv/bin/python -m jarvis.modules.voice.say "текст" ruslan` — синтезирует и печатает размер, не отправляя.
5. Если менялся код озвучки или доставки — ПЕРЕЗАПУСТИТЬ демон ВК, иначе правка не действует, и проверить живым сообщением.

## Известные грабли
Opus принимает только 8/12/16/24/48 кГц. Piper-medium отдаёт 22050. Пропустить ресемпл — получить LibsndfileError уже на записи файла, до всякого ВК.

ffmpeg на машине нет и не будет (нужен sudo). Всё кодирование — через soundfile, не через вызовы внешних утилит.

Имя поля в multipart — ровно "file", имя файла — "file0.ogg". Другое имя ВК молча не примет.

access_key у сохранённого документа может отсутствовать — подставлять его в строку вложения только если он есть.

Длинный текст голосом не отправлять: слушать пять минут монолога невозможно. Голос — для короткого, текст — для разборов.

ПРОВАЛ 22.08: смена голоса на ruslan в say.py не изменила ничего в чате — работающий демон держит код в памяти с момента старта. Правка модуля считается сделанной только после перезапуска демона и живой проверки. Сверка: `ps -o lstart= -p <pid>` против `stat -c '%y' <файл>`.

Долгую внешнюю операцию запускать так, чтобы результат оставался на диске (лог, файл), а не только в выводе команды.
