# План проверки критериев — t-003 (карта дисков), заход 1

Заход 1 не собирает данные по дискам — только ветка и план. Второй заход
проверит план на живых числах.

- c-01: отчёт — файл `derived/vnutrennii/t-003/disk-report.md`. Числа беру
  командой `du -x --max-depth=2 <точка монтирования sda2>` (флаг `-x` держит
  du в пределах одной файловой системы, не уходит на смонтированные внутрь
  разделы), сортирую по убыванию, перевожу КБ в МБ/ГБ, кладу топ каталогов
  таблицей в отчёт.

- c-02: тот же файл, два раздела: «Кандидаты на удаление» (кэши apt/pip/npm,
  старые ядра, snap-ревизии, journal-логи, корзина, build-мусор) и «Кандидаты
  на перенос» (крупные неизменные данные — архивы, медиа, старые бэкапы).
  У каждого пункта — своя оценка МБ, посчитанная тем же `du` по конкретному
  подкаталогу.

- c-03: сумма МБ по всем пунктам топ-каталогов (не только кандидатов, а
  полного разбора первого уровня diff, из которого собраны c-01/c-02) кладу
  в питон-выражение: `abs(sum(items_mb) - 162*1024) / (162*1024)`. Число
  и формула — прямо в отчёте, чтобы тимлид пересчитал сам не запуская код.
  Порог — не больше 0.15.

- c-04: перед тем как путь попадёт в отчёт, проверяю `Path(p).exists()` в
  питоне (или `test -e` в шелле) для каждого пути и в отчёте помечаю только
  подтверждённые; непроверенные в отчёт не идут.

- c-05: скрипт переноса — отдельный файл
  `derived/vnutrennii/t-003/perenos-nadis.sh` (или `.py`), не запускается ни
  разу в ходе задачи. Доказательство «не запускался»: `stat` на файл сразу
  после записи покажет mtime записи и совпадёт с временем последнего Write;
  дополнительно — снимок каталога `derived/vnutrennii/t-003/` до и после
  работы (`ls -la`) не покажет новых файлов, которые создал бы перенос.
  Скрипт первой же командой проверяет `mountpoint -q <путь_назначения> ||
  exit 1` (или её питон-аналог `os.path.ismount`), прежде чем делать что-то
  ещё.

- c-06: перед стартом сбора данных снимаю снимок состояния — вывод `du -x
  --max-depth=1 <точка монтирования>` в файл
  `derived/vnutrennii/t-003/before.txt`; после завершения работы — второй
  снимок `after.txt` тем же способом. Файлы совпадают (diff пустой) — это и
  есть доказательство, что ничего не удалено и не перемещено. Снимки кладу в
  derived как одноразовую проверку (правило odnorazovye-proverki-v-derived).

- c-07: заход 1 уже закрыл эту часть — ветка `agent/t-003-karta-diskov`
  заведена через `modules/projects/branches.py` (`branch-create`), рабочий
  каталог `../worktrees/agent__t-003-karta-diskov`, база `master`, HEAD
  основного репозитория не менялся. Доказательство на сдаче — `git -C
  jarvis log master --oneline -3` без новых коммитов исполнителя и `git -C
  worktrees/agent__t-003-karta-diskov log --oneline` с коммитами работы
  второго захода.
