# Память v2 — предложение

## 1. Что сейчас (замеры на 23.08.2026, второй день жизни)

Контекст собирается в `core/memory.py:build_context()` и уходит в модель ЦЕЛИКОМ каждый медленный ход:

| блок | как грузится | размер сейчас |
|---|---|---|
| конституция | целиком | 15,6 КБ |
| now.md | целиком | 2,2 КБ |
| обязательства | все open | 4,1 КБ |
| правила | ВСЕ active | 5,9 КБ (5 шт.) |
| реестр способностей | целиком | 0,6 КБ |
| сырой лог | 7 дней, обрезка 40 КБ с хвоста | 40 КБ (реально накоплено 600 КБ за 2 дня) |
| свёртки | недели+месяцы | 0 (ночной цикл ни разу не отработал) |
| факты | ВСЕ | 14,5 КБ (13 шт.) |
| процедуры | ВСЕ | 10,4 КБ (4 шт.) |

Итого системный промпт 115 КБ при жёстком потолке 128 КБ (MAX_ARG_STRLEN ядра). Превышение = ход не начинается вовсе.

**Стена не через месяц, а через 5-7 дней.** Темп: ~6 фактов, ~2 процедуры, ~2 правила в день. Через месяц: ~180 фактов ≈ 200 КБ — в полтора раза больше всего лимита. Через год — десятки мегабайт при неизменном потолке.

Второй дефект — поиск. `memory.search()` линейно перебирает лог и факты, считает совпадения слов подстрокой, без морфологии. На русском «письмо / письма / письму / письмами» — разные строки: половина запросов не найдёт то, что лежит рядом. Ранжирования нет (score = число слов запроса).

Третий дефект — плоскость. Факты лежат одной кучей, поле `links` не заполняется, иерархии целей нет. Ответить «что мы вообще пробовали ради миллиона в месяц и чем кончилось» нечем.

## 2. Принципы v2

1. **В контекст по умолчанию — карта, а не территория.** Постоянно грузятся: конституция, now, обязательства, реестр, оглавление памяти (id + строка + теги, ~80 байт на запись) и лог последних часов. Содержимое фактов, процедур, эпизодов достаётся инструментом по требованию (just-in-time retrieval — практика Anthropic для долгих агентов).
2. **Дерево целей — навигационный хребет, знания — граф.** Идея Ильи про 5 уровней принимается как СТРУКТУРА РАБОТЫ, но знания на неё не насаживаются: «как отправлять почту через mail.ru» нужно в трёх ветках сразу. Дерево отвечает «где мы и что пробовали», граф тегов и ссылок — «что я об этом знаю».
3. **Два контура, как у людей.** Рабочая память: now + фокус текущей ветки + свежий лог, объём фиксирован. Долговременная: всё остальное, вне контекста, достаётся поиском. Перенос из первой во вторую — консолидация в простое и ночью (sleep-time compute, Letta).
4. **Факты не удаляются, а закрываются во времени.** У записи `valid_from` / `valid_to`. Новый факт вытесняет старый явно. Это лечит главный провал векторной памяти: «переехал в Мадрид», а агент через три хода советует рестораны в старом городе.
5. **Каждая запись обязана иметь связи.** При записи — теги + links на соседние id, и обновление соседей (механика A-MEM: заметка + связи + эволюция старых заметок; заявленный эффект — кратный рост на многошаговых вопросах и −85..93% токенов на операциях памяти).
6. **Старение.** У записи `hits` и `last_used`. Не использовалось 60 дней и не помечено якорем → `dormant`: уходит из оглавления, остаётся в поиске.
7. **Проверяемость.** Набор из ~30 контрольных вопросов по прожитому («когда ушли первые письма», «почему падал промпт», «какой пароль нужен mail.ru»). Регрессия: агент обязан найти ответ за ≤2 обращения к памяти. Это единственный способ отличить работающую архитектуру от красивой.

## 3. Структура

```
memory/
  log/YYYY-MM-DD.jsonl        эпизоды, только дозапись        (как сейчас)
  now.md                      рабочая память                  (как сейчас)
  obligations.md              механический реестр             (как сейчас)
  registry.md                 способности                     (как сейчас)
  goals/
    g1-million/goal.md        L0: цель, метрика, срок, статус
    g1-million/n-studii/branch.md      L1: ниша/направление
    g1-million/n-studii/e01-rassylka.md L2: эксперимент — гипотеза, что сделано,
                                        метрика, вывод, ссылки на лог и факты
  facts/<id>.md               семантика                       (+ valid_to, tags, links)
  procedures/<id>.md          процедуры                       (как сейчас)
  rules/<id>.md               правила                         (+ tags для выборочной загрузки)
derived/
  index/memory.db             SQLite: FTS5 + метаданные + (позже) вектора
  index/map.md                оглавление, генерируется из индекса
  rollups/                    свёртки недель и месяцев
```

Уровень «3 слова про этап переписки» из идеи Ильи реализуется не отдельным слоем, а полем `episode` у события лога + строкой в карточке эксперимента: иначе получается пятый формат, который надо вести руками.

## 4. Поиск

SQLite FTS5 (BM25) по логу, фактам, процедурам, карточкам экспериментов. Лемматизация русского при индексации (pymorphy3 — иначе морфология съедает половину попаданий). Фильтры по структуре до поиска: ветка, даты, тип, статус.

Вектора — вторым этапом и только если FTS5 начнёт промахиваться на контрольных вопросах. Тогда multilingual-e5-small (118M, CPU, русский поддержан) + sqlite-vec, слияние с BM25 по RRF. Индустрия сходится: чистый вектор проигрывает гибриду, а графовые БД дороги в перестройке.

## 5. Порядок работ (по одному шагу, каждый с проверкой)

1. **Снять давление на промпт** (срочно): факты и процедуры из постоянного контекста → в оглавление + инструмент `recall`. Ожидаемый эффект: промпт 115 КБ → ~55 КБ, потолок перестаёт быть угрозой. Риск: агент перестанет «случайно» видеть нужный факт — лечится оглавлением и контрольными вопросами.
2. **Индекс FTS5 + лемматизация**, `recall` возвращает куски с оценкой; замер на 30 контрольных вопросах до и после.
3. **Дерево целей** goals/ + карточки экспериментов; перенос текущей работы (рассылка) в первую ветку.
4. **Консолидация**: ночной цикл по cron + работа в простое (см. предложение об автономном режиме); старение и `valid_to`.
5. **Вектора** — только по факту промахов, не раньше.

## 6. Чего сознательно не делаем

Графовой базы (Neo4j и подобное), собственного векторного сервиса, фреймворков памяти (Mem0/Letta/Zep) внутрь себя, переписывания всей памяти разом. Причина одна: данные должны остаться markdown+JSONL, читаемыми любым будущим кодом. Индекс — производное, сносится и пересобирается.
