**Правило:** В репозитории агента не пользоваться git stash — ни руками, ни из кода (subprocess.run с 'stash' — то же самое действие). Чтобы проверить «было ли сломано до моей правки», делать копию файлов в `derived/scratch/<дата>-<зачем>/`, а рабочее дерево не откатывать.
**Почему:** 26.08 я нарушил собственное правило изнутри питон-скрипта: захотел сравнить старое и новое поведение шлюза и вызвал subprocess git stash. Стэш забрал не только правку ядра, но и живой лог — 430 строк memory/log/2026-08-26.jsonl исчезли из рабочего файла, то есть я задел неизменяемую зону. Вернуть pop не дал конфликт (демон дописывал лог), пришлось вынимать файлы поштучно из stash и дозаписывать потерянные строки. Правило было записано, но проверялось только моей памятью и только для команды в шелле — вызов из кода мимо неё прошёл.
**Как применять:** Нужно старое поведение кода — не откатывать дерево, а достать старую версию рядом: `git show <коммит>:core/agent.py > derived/scratch/<дата>/agent_old.py` и импортировать её как отдельный модуль. Если стэш всё-таки сделан: НЕ пытаться pop при живом логе (конфликт гарантирован), а вынуть нужные файлы `git checkout stash@{0} -- <пути>`, затем сверить лог по числу строк и дозаписать пропавшее только через append.
