# modules/jobs — процесс-подагент

Исполнительная половина механизма заданий. Диспетчер и журнал живут в
`core/jobs.py`, здесь только то, что запускается отдельным процессом ОС.

| файл | что делает |
|------|------------|
| `run.py` | один ход по брифу задания и запись результата в файл. Запускается диспетчером, не человеком |
| `cli.py` | пульт: поставить задание, посмотреть журнал, забрать результат |

## Зачем отдельный процесс

Ход агента — одноразовый вызов SDK: он умирает на результате и уносит с собой
всё, что запущено внутри, включая подагентов инструмента `Agent`. Между ходами
агента не существует (факт `agent-sobytiyniy`), поэтому принять результат
некому — если только исполнитель не переживает ход. Отдельная сессия ОС
(`start_new_session=True`) переживает и ход, и перезапуск демона; результат
достаётся из файла, а не из чьей-то памяти.

Заодно это единственный безопасный способ параллелиться: `core/agent.py`,
`core/heartbeat.py` и `core/interrupt.py` держат состояние в модульных
переменных, то есть два хода в одном процессе портили бы друг другу прогресс,
пульс и прерывания. Один процесс — один ход, правило не нарушено.

## Как поставить задание

```
cd "…/Agent"
jarvis/.venv/bin/python -m jarvis.modules.jobs.cli submit "имя задания" \
    --model haiku <<'EOF'
Задача: одним предложением.
Где искать: конкретные пути и источники.
Что можно самому: …
Что только с моего согласия: …
Формат результата: выжимка плюс путь к сырым данным.
Критерии приёмки: проверяемые.
EOF
```

Команда возвращает управление сразу — ход продолжается, разговор в ВК не
встаёт. Результат подложит демон: в промпт следующего хода Ильи (`take_inbox`)
либо, если Илья молчит, отдельным ходом-докладом (`take_report`). Ночью
доклад копится до утра — правило `nochnaya-tishina`.

Остальные команды: `list`, `show <id>`, `result <id>`, `wait <id>`, `tick`,
`capacity`. Ждать задание в том же ходе (`wait`) можно, но обычно не нужно:
ради того, чтобы не ждать, всё и сделано.

## Что помнить

- Бриф обязан быть самодостаточным: подагент видит только его и не может
  спросить Илью сам.
- Подагент не пишет Илье ничего и никогда — докладывает главный агент своей
  выжимкой (правила `dnyom-rabotayut-podagenty`, `kratkost`).
- Модель выбирает главный: haiku на механическое, sonnet на думающее.
  Opus подагентам не даётся.
- Сколько заданий пойдёт разом, решает железо, а не деньги: `capacity()`
  считает ядра и свободную память в момент запуска.
- Журнал, брифы и результаты — в `memory/jobs/`: результат работы подагента
  не пересоздаётся ничем (правило `v-derived-tolko-vosstanovimoe`).
  В `derived/jobs/` только сырой вывод процесса, он одноразовый.
