# modules/projects — протокол задачи

Измерение проекта в памяти (`memory/projects/<проект>/`) и протокол задачи из
трёх файлов с разными владельцами, описанный в разделе 3 документа
«Джарвис — команда и проекты» (этап 0, раздел 13).

| файл | что делает |
|------|------------|
| `tasks.py` | ядро протокола: create/plan/submit/accept/check/overdue/status |
| `cli.py`   | пульт: те же действия из командной строки |

## Три файла задачи

Папка `memory/projects/<проект>/tasks/<id>/`:

- `task.md` — пишет тимлид, исполнитель читает. Разделы по приоритету: даты,
  цели, критерии, границы, связи, материалы. **Потолок 100 строк** —
  проверяется машинно при заведении и при каждом круге доработки.
- `task.json` — критерии приёмки, статус меняет только тимлид. Подмена текста
  пункта задним числом ловится `check()` сравнением с первой закоммиченной
  версией файла через `git log --follow --diff-filter=A`.
- `progress.md` — ведёт исполнитель: план проверки (обязателен до `submit`),
  журнал работы, вопросы.

## Ход работы

```
create   → (тимлид заводит task.md + task.json)
plan     → (исполнитель: как проверю каждый c-NN — без этого submit откажет)
submit   → (исполнитель сдаёт, называет артефакты; закрыть сам не может)
accept   → (только тимлид: verdict done — все критерии обязаны быть passes;
            verdict rework — новый круг, дописывается в task.md, до 3 кругов)
check    → (машинная проверка: артефакт есть/не пуст/не старше начала задачи,
            все критерии passes, task.md ≤100 строк, критерии не подменены)
```

## Как поставить

```bash
cd "…/Agent"
jarvis/.venv/bin/python -m jarvis.modules.projects.cli create vnutrennii \
    --title "..." --teamlead jarvis --executor sonnet-1 \
    --planned-due 2026-09-01 \
    --criteria "первый пункт" --criteria "второй пункт"

jarvis/.venv/bin/python -m jarvis.modules.projects.cli status vnutrennii
```

## Что важно помнить

- Роль передаётся аргументом (`actor=`/`--role`), не выводится из процесса:
  разделение прав держит код, а не то, кто вызвал функцию.
- Артефакт обязателен для `check()`: без файла или ссылки, названных при
  `submit`, задача не проходит проверку — раздел 4 документа.
- `PROJECTS_DIR` — модульная константа в `tasks.py`, читается заново при
  каждом вызове (не захватывается в момент импорта) — самотест подменяет
  именно её, а не `core/config.py` (правило `samotest-ne-pishet-v-zhivuyu-pamyat`,
  урок bl-118).
- Изоляция зоны «роль проекта не видит чужой проект» (раздел 6.2 документа) —
  **не сделана**: у механизма заданий (`core/jobs.py`) зона режется по роли, а
  не по проекту, и правка шлюза (`core/agent.py`) в этой работе запрещена.
  Нужно отдельное подтверждение Ильи.
