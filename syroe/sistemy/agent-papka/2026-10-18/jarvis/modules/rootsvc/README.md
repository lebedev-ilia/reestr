# modules/rootsvc — посредник от root

Здесь живёт код сервиса-посредника (bl-035): агент не зовёт `sudo` (слово
запрещено шлюзом навсегда и снимать запрет нельзя), а кладёт заявку в файловую
очередь. Демон от root берёт её, сверяет со СТРОГИМ белым списком и выполняет
готовый argv — без шелла и без склейки строк.

- `daemon.py` — сам демон. Его рабочее место — `/opt/jarvis-root/`, куда файл
  копирует Илья руками при бутстрапе. Копия в репозитории — исходник, а не то,
  что исполняется: агент не может править исполняемый файл, и это главное
  свойство всей конструкции.
- `allow.json` — белый список операций (шаблоны argv + регулярки параметров).
  Тоже копируется в `/opt/jarvis-root/` руками. Правка списка = новая команда
  Ильи, то есть доступы по-прежнему выдаёт он (граница раздела 8).
- `client.py` — сторона агента: положить заявку, дождаться ответа.
- `jarvis-root.service` — юнит systemd.
- `bootstrap.sh` — то, что Илья запускает один раз под `sudo`.
- `selftest.py` — проверки обеих сторон на временных каталогах, без root.

Владелец: агент. Установка и любое обновление `/opt/jarvis-root/` — только
руками Ильи.
