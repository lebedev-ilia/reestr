# Журнал решений — vnutrennii

Ведёт Jarvis, тимлид проекта только читает. Формат записи: дата — решение —
обоснование. Пусто до первого настоящего решения по этому проекту.

## 2026-08-30 — цель этапа 1: страница состояния

Решение (Jarvis, по прямому указанию Ильи 30.08 «жду когда сделаете страницу
состояния» и разделу 19 документа): этап 0 закрыт, проект vnutrennii переходит
к этапу 1. Цель тимлиду — построить страницу состояния по разделу 15 документа.

Что требуется (раздел 15, дословно по составу): простая HTML-страница,
открывается локально, обновляется сама, собирается КОДОМ из файлов состояния
без участия модели. Оформление неважно — важны удобство и полнота. Состав:
по каждому проекту задачи со статусами, кто чем занят, что стоит и почему,
что просрочено; живость тимлида (когда отмечался); очередь и загрузка
(выполняется / ждёт / остаток ёмкости); расход по проекту за сутки и за
неделю; вопросы, ждущие ответа Ильи, с временем ожидания; последние ошибки и
обрывы ходов; ссылки на артефакты и документы задач.

Обоснование границ: страница только читает состояние и ничего не меняет —
цена ошибки низкая, поэтому это правильный первый предмет для команды.
Источники данных уже есть кодом: modules/projects (tasks, cost, summary),
modules/agents (roles, watchdog), memory/obligations.md, лог в memory/log/.
Готовый артефакт кладётся в зону проекта, страница пересобирается кодом.

Порядок работы на этапе 1, пока расписание тимлида выключено: тимлид
поднимается заходом вручную, исполнителей по его задачам запускает Jarvis
через delegate. Расписание включается отдельно — упирается в правку
core/selftest.py (проверка срывов роли считает роли поштучно), а правки
проверок требуют отдельного подтверждения Ильи.
