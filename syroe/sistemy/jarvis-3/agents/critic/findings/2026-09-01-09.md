## 2. Неизменяемая зона `memory/log/` не защищена гитом на 30+ часов
`git status --short --untracked-files=all -- memory/log/`:
```
 M memory/log/2026-08-30.jsonl
?? memory/log/2026-08-31.jsonl
?? memory/log/2026-09-01.jsonl
```
`git diff --stat -- memory/log/` → `2026-08-30.jsonl | 3675 +++...` (только
вставки). В гите закоммичено 502 строки этого файла (коммит 09:56:48 30.08),
в рабочем дереве — 4177 (последняя строка 30.08 23:55). Файлы 08-31 и 09-01
не в гите вообще ни строкой.

**Почему плохо.** Конституция, раздел 9: `memory/log/` — «неизменяемое.
Только дозапись. Не редактируется и не удаляется никогда» — но гарантия эта
держится ТОЛЬКО гитом (или диском, который может отказать). Прямо сейчас
почти два полных дня живого лога (единственный источник «что реально
произошло» для recall, самоаудита, ежемесячной ревизии) существуют в одной
копии на одном диске. Ночной автокоммит (ob-102) в своей нынешней
формулировке чинит только `memory/projects/**` и `memory/agents/**` — про
`memory/log/` там речи нет вообды, а это самая ценная из трёх зон по
собственному определению раздела 9.

**Что делать.** Не точечная правка путей в ob-102, а либо коммит
`memory/log/<сегодня>.jsonl` чаще (например, каждым ночным циклом и/или
каждым закрытием дня), либо отдельный частый коммит just для `memory/log/`
вне общего автокоммита memory/projects. Решение — не моё.
