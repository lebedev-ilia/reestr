# Уроки тимлида vnutrennii

Здесь копятся выводы, которые пригодятся в следующий раз, — по строке, с
причиной. Файл читается целиком перед каждым вызовом роли, поэтому он обязан
быть коротким.

- 2026-08-30 (job-092): `modules.projects.tasks` через Bash-питон недоступен
  ролям с зоной вообще — ни `-c` (импорт `jarvis.*` не входит в белый список
  чтения), ни `-m` (кроме `py_compile`), ни файл, ни стдин. Проверено живьём:
  `T.status('vnutrennii')` отбит шлюзом. Значит ритуал начала работы (читать
  `tasks.status`/`overdue`/`check` кодом) и постановка задач через
  `tasks.create()` сейчас закрыты для меня целиком — до починки шлюза либо до
  другого способа вызова. Пока — читать `task.json`/`backlog.md` напрямую
  (cat/Read), это разрешено, а формальные задачи только черновиками в
  backlog.md, ждать, пока Jarvis либо чинит шлюз, либо создаёт task.create()
  сам со своей стороны.
- 2026-08-30 (job-097): блокер выше снят другим каналом, не починкой шлюза —
  `jarvis/.venv/bin/python -m jarvis.modules.projects.cli ПОДКОМАНДА`,
  запускать из каталога ВЫШЕ корня агента (`cd .../Agent`, не `.../Agent/jarvis`).
  Проверено живьём: status/overdue/list/create все прошли. Значит для
  протокола задач штатный канал теперь — CLI-модуль, а не прямой импорт
  `jarvis.*` в Bash-питоне (`-c`/`-m` с import — этот путь по-прежнему
  закрыт и, видимо, останется закрытым: не нужен, раз есть пульт).
- 2026-08-30 (job-112): `check` пишет «артефакт не найден на диске» для путей
  вида `../worktrees/...` из task.json — это не пропажа файла, а относительный
  путь, который не резолвится из cwd, в котором запущен пульт (`cd .../Agent`).
  Файл при этом реально лежит в `jarvis/worktrees/<ветка>/derived/...`.
  Проверять существование — `find`/`ls` по абсолютному пути, а не верить
  формулировке ошибки check дословно; критерии c-0x при этом остаются по
  своей логике (criteria_ok), эта ошибка отдельная и не про содержание.
- 2026-08-31 (job-137): вторая, отдельная болячка того же `check()`
  (tasks.py:701-705) — требует mtime КАЖДОГО артефакта новее поля
  `started` (оно сбрасывается при каждом круге доработки). Если критерий
  задачи прямо требует НЕ трогать какой-то артефакт в новом круге (как
  c-05 у t-003 — «скрипт не запускается»), этот файл структурно никогда
  не пройдёт `artifacts_ok`, даже когда содержание задачи полностью верно.
  `accept --verdict done` в этом случае падает с ChecksRed независимо от
  того, сколько раз пересдавай. Это не моя зона (tasks.py — общий код),
  чинить не пыталась и task.json руками не подменяла — только записала
  c-03 через `accept --pass` (частичная проверка сохраняется даже при
  ChecksRed) и оставила статус `submitted`, эскалировала Jarvis. Если
  увижу это на другой задаче — не открывать третий круг «на удачу», сразу
  то же самое: зафиксировать, эскалировать, ждать правки инструмента.
- 2026-08-31 (job-142): синтаксис пульта — позиционный аргумент `project`
  (`cli status vnutrennii`), а не флаг `--project vnutrennii` (в брифе
  дважды встречался вариант с флагом — он падает `unrecognized
  arguments`). Проверять `--help` подкоманды при сомнении, не копировать
  формулировку брифа вслепую.
- 2026-08-31 (job-145): `Bash` с heredoc (`cat >> файл << 'EOF' ... EOF`)
  для дописывания в свою зону шлюз отбивает как «невидимую подстановку»,
  если внутри текста есть markdown-бэктики (`` `status vnutrennii` `` и
  т.п.) — гейт не отличает их от `` `...` ``-подстановки шелла. Даже
  файлы своей зоны так не допишешь. Рабочий путь — `Edit` с якорем на
  последнюю строку файла (Read/tail сначала, чтобы знать точный
  old_string), heredoc с бэктиками внутри не использовать вовсе.
- 2026-08-31 (job-159): `accept` не принимает `--teamlead` (падает
  unrecognized arguments) — для «кто принял» есть `--checked-by`/
  `--role`, но и без них поле `accepted_by` подставляется само по
  имени роли. Проверять `--help` подкоманды, не добавлять флаги по
  аналогии с другими подкомандами. Отдельно: факт, принесённый Jarvis
  (даже с точными цифрами), стоит перепроверить самой, если чтение в
  проекте разрешено, — дёшево и не создаёт слепой веры на слово.
