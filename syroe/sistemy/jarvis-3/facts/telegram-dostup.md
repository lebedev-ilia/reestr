Исследование 24.08.2026. Главная находка: между «просто бот» и «userbot с риском бана» есть третий, штатный путь, о котором мало кто знает.

УРОВЕНЬ 1. BOT API через @BotFather. Прямой аналог канала ВК: long polling, тот же код по структуре. Умеет текст, голосовые (sendVoice, ogg/opus), файлы, приём и скачивание голосовых от Ильи. Не умеет: писать первым тому, кто не нажал /start; видеть переписку Ильи с другими; читать историю до себя. Скачивание файлов ограничено 20 МБ (голосовому хватает с запасом), снимается своим локальным Bot API server. Риск нулевой — аккаунт Ильи не участвует вообще. Собирается за 2–4 часа.

УРОВЕНЬ 2. TELEGRAM BUSINESS CONNECTED BOT — тот же бот, но действует ОТ ИМЕНИ Ильи. Официальный механизм с Bot API 7.2 (март 2024), расширен в 9.0. Бот получает business_message — входящие личные сообщения Ильи от других людей — и отвечает так, что сообщение выглядит отправленным Ильёй. Голосовые от его имени тоже: любой send-метод с параметром business_connection_id. Права выдаются галочками (BusinessBotRights: читать, отвечать, удалять), адресаты выбираются (все чаты / только новые / только контакты), любой чат ставится на паузу или исключается. ОГРАНИЧЕНИЯ: только личные чаты, никаких групп и каналов; истории нет — видны только сообщения с момента подключения; пересылать сообщения из управляемого чата наружу нельзя; один business-бот на аккаунт. Риск нулевой — это штатная функция, ровно для этого сделанная. Включается так: в BotFather у бота включить Business Mode, затем в приложении Настройки → Telegram Business → Чат-боты вписать бота. НЕ ПРОВЕРЕНО: документация пишет «Premium не требуется», но сам раздел Telegram Business в приложении исторически премиальный — нужно посмотреть на телефоне Ильи, есть ли этот пункт.

УРОВЕНЬ 3. USERBOT (Telethon) — всё, что видит Илья: группы, каналы, полная история, поиск, файлы до 2 ГБ. Нужен только ради групп, каналов и истории; публичные каналы при этом читаются вообще без аккаунта через t.me/s/<имя>.

СОСТОЯНИЕ БИБЛИОТЕК НА 08.2026, ЭТО ЛЕГКО ПЕРЕПУТАТЬ. Pyrogram МЁРТВ: upstream заархивирован 23.12.2024, последний релиз 30.04.2023. Все живые «pyrogram» на PyPI — форки третьих лиц (kurigram самый бодрый). Telethon ЖИВ, но ПЕРЕЕХАЛ С GITHUB НА CODEBERG: репозиторий на GitHub заархивирован 21.02.2026, что легко принять за смерть проекта. Живой дом — codeberg.org/Lonami/Telethon, слой MTProto 229 подтянут 23.08.2026. Формально maintenance mode, для демона это плюс.

ПРО БАН — ЧТО НАПИСАНО, А НЕ СЛУХИ. core.telegram.org/api/obtaining_api_id: банят навсегда за флуд, спам и накрутку; аккаунты с неофициальными клиентами «автоматически ставятся под наблюдение». То есть userbot не запрещён как класс, но порог антиспама для аккаунта снижается. ToS п. 1.4 запрещает действия от имени пользователя БЕЗ ЕГО ВЕДОМА И СОГЛАСИЯ — личный userbot самого владельца под это не подпадает, и именно эта формулировка его легитимизирует. Отдельно ToS п. 1.5: запрещено использовать данные Telegram для обучения и разработки моделей ИИ. Прогон сообщения через LLM ради ответа — не обучение, но формулировка размытая; практический вывод — не копить чужие сообщения в долгую память.
Факторы риска, названные документацией Telethon прямо: РФ, Иран, Казахстан, Китай; НОВЫЕ аккаунты; ВИРТУАЛЬНЫЕ номера. Разобранный реальный кейс банов (issue 3955) — это четыре свежих аккаунта на VoIP-номерах с немедленной автоматизацией, то есть банили за профиль спамера, а не за userbot. Диагностика ограничений — написать @SpamBot; признак — ошибка PeerFloodError.
АСИММЕТРИЯ, КОТОРАЯ РЕШАЕТ ВЫБОР: выигрыш от userbot — удобство, проигрыш — весь аккаунт Telegram целиком (контакты, переписка, каналы), апелляция на recover@telegram.org рассматривается непредсказуемо.

ГОЛОСОВЫЕ. Формат обязателен: контейнер OGG, кодек OPUS, моно, 48 кГц, 24–48 кбит/с — иначе уедет обычным аудиофайлом, а не пузырём с волной. Конвертация: ffmpeg -i in.wav -c:a libopus -b:a 32k -ar 48000 -ac 1 out.ogg. Грабля Telethon (issue 4170): при отправке из BytesIO кэш игнорирует атрибуты и файл уходит не тем типом — слать с диска из временного файла.

ЭКСПЛУАТАЦИЯ USERBOT, ЕСЛИ ДОЙДЁТ. Файл сессии — эквивалент пароля от аккаунта, права 600, вне git и облаков. Один файл — один процесс, иначе порча ключа. api_hash отозвать невозможно. Различать ошибки: FloodWaitError — ждать столько, сколько сказано, а не ретраить; PeerFloodError — аккаунт ограничен, немедленно прекратить отправку и разбудить Илью; AuthKeyUnregistered / SessionRevoked / UserDeactivatedBan — нужен человек.
