- Факт memory/facts/sborka-konteksta-ustroystvo.md и memory/facts/potolok-sistemnogo-prompta.md — прочитать целиком ПЕРЕД работой, там описан приём «голова в промпт, хвост через Read».
- Расход: modules/audit/spend.py (посмотреть его README и код, понять интерфейс) и живой лог memory/log/2026-09-01.jsonl, записи self с полями cost_usd и tokens.
- Число файлов памяти: memory/facts, memory/procedures, memory/rules.

## Что нужно померить
1. Полный размер системного промпта медленного хода в БАЙТАХ и разбивку по каждому блоку (конституция, обязательства, now, правила, реестр, оглавление фактов, оглавление процедур, оглавление правил, хвост лога, свёртки, наблюдение о себе). Мерить кодом — вызвать сборку промпта из core/memory.py в отдельном скрипте в derived/scratch/, а не считать на глаз.
2. Для каждого блока: сколько байт, какой потолок стоит в core/config.py, режется ли блок сейчас (да/нет, на сколько байт).
3. Число файлов в memory/facts, memory/procedures, memory/rules; суммарный объём каждого каталога в байтах; средняя длина строки оглавления в байтах.

5. Расход за сутки 2026-09-01 целиком: число ходов, токены (вход, выход, чтение кэша, запись кэша), сумма cost_usd. Отдельно — та же пятёрка за 2026-08-31 для сравнения.

1. Сумма байт по блокам совпадает с полным размером промпта (расхождение не больше 2%).
2. Для каждого блока видно, режется он сейчас или нет.
3. Команды из раздела «Как повторить замер» реально прогнаны тобой и работают.
4. git status показывает изменения только в derived/ — ни одного изменённого файла в core/ и memory/.
