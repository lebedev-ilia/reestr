## Предусловия
В .env есть HH_LOGIN (email, без пароля — вход у hh только по коду) и рабочий IMAP-доступ (GMAIL_USER/GMAIL_APP_PASS, см. факт gmail-imap-dostup). Playwright с chromium стоит в .venv проекта (поставлен 24.08).

## Шаги
1. Playwright, persistent context в derived/hh_profile (там уже есть активная сессия от 24.08 — сначала попробовать без повторного логина, открыть hh.ru с этим профилем).
2. Если сессии нет/истекла: открыть hh.ru → «Войти» → роль «Я ищу работу» → вкладка «Почта» → ввести HH_LOGIN из .env → «Дальше» — это отправляет письмо с кодом на GMAIL_USER.
3. Через 5-10 сек прочитать по IMAP свежее письмо от noreply@hh.ru с темой «Код подтверждения», ОБЯЗАТЕЛЬНО декодировать MIME-заголовок Subject (email.header.decode_header) — иначе фильтр по теме тихо пропускает письмо. Код искать в HTML-теле по шаблону вида `>NNNN<`.
4. Использовать код с первой попытки: каждый повторный клик «Дальше» шлёт НОВОЕ письмо и инвалидирует предыдущий код — старый даёт «Неверный код», это не защита, а просто протухший код.
5. Ввести код, дождаться редиректа на личный кабинет (khabarovsk.hh.ru/, шапка с «Резюме и профиль»/«Отклики» вместо кнопки «Войти») — это и есть признак успеха.

## Известные грабли
Кнопка «Войти» — span внутри a[role=button], обычный .click() таймаутит из-за перехвата указателя дочерним элементом — кликать force=True. После входа НИЧЕГО больше не делать на hh (не открывать вакансии, не листать резюме, не откликаться) — соглашение hh запрещает скрипты/роботов (п.8.8), это должен выглядеть как разовый ручной вход, не сессия автоматизации. Капчи и доп.2FA по пути не возникало ни разу, но если появятся — останавливаться, не обходить.
