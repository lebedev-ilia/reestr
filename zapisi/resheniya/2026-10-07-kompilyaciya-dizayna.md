План был предложен в документе systema_plan.md (свидетельство

## Почему не строить напрямую

Журнал — это «почему», а разработчику нужно «что и как». Из 40k строк
рассуждений исполнительная часть должна ужаться до 2–5k строк. Без шага
компиляции к вопросу 123 получили бы 40k строк, из которых реализуемо 5%.

## Три документа из одного журнала

1. **Design Rationale** — текущий журнал как есть. Не трогаем, растёт дальше.
   Нужен для traceability: «почему приняли именно это».
2. **Implementation Specification** — выжимка только «что строим»: диаграммы
   компонентов, схемы данных (Pydantic/JSON Schema), state machines,
   API-контракты, конфиги (YAML), acceptance-тесты. 2–5k строк.
3. **Implementation Roadmap** — последовательность сборки, фазы 0–5,
   критерии перехода между фазами. 500–1000 строк.

## Walking Skeleton v0.1 (2–4 недели)

Минимальный сквозной срез — одна вертикаль через всю архитектуру, без
полировки. Критерий успеха: «Пользователь даёт задачу → Джарвис
декомпозирует → Тимлид назначает исполнителя → Исполнитель выполняет →
Результат возвращается пользователю».

| Компонент | Минимум | Что НЕ делаем |
|---|---|---|
| Пользователь | CLI-команда | UI, push-уведомления |
| Джарвис | 1 инстанс, Claude Sonnet | Adaptive autonomy, T3/T4 |
| Тимлид | 1 инстанс | Span of control, failover |
| Исполнитель | 1 инстанс | Pool, reuse |
| Память | 1 слой (project), SQLite | 4 слоя, DAG, bi-temporal |
| Инструменты | 3–5 штук, MCP | Registry, discovery, synthesis |
| PDP/PEP | Allowlist по ролям | Derivation-gated, AKAC |
| Аудит | SQLite append-only | Merkle, witnesses |
| Handoff | JSON-объект | H_exact/H_stat/H_residual |
| Эскалация | 3 триггера | 9 триггеров, VAIL gates |

Фазы после skeleton: Foundation (+1 мес: память 4 слоя, L0–L5, escalation
protocol) → Coordination (+1 мес: queue, async, circuit breaker) →
Intelligence (+2 мес: routing, memory quality, consolidation) → Scale (+2 мес:
multi-tenancy, quotas, federation) → Advanced (по потребности).

## Правила процесса

- Каждое решение журнала получает тег: **[MVP] / [Foundation] / [Scale] /
  [Advanced] / [Research]** — и попадает в master index (одна строка на
  решение, ~200 строк на все 124 вопроса).
- Компиляция — раз в 10 новых вопросов, не реже.
- Проектирование считается «достаточным», когда все [MVP]-решения
  зафиксированы и skeleton можно начинать. Остальное уточняется по ходу.

## Следующие шаги (порядок важен)

1. **Master Index** — 124 решения → ~200 строк с тегами приоритета. (начать сразу)
2. **Executable artifacts** — схемы данных (из В3, 41, 46, 48), state machines
   (В6, 39, 52, 56, 57), конфиги (В9, 11, 27, 37, 52), acceptance-тесты
   (В45, 47, 52, 56) → папка spec/.
3. **Implementation Roadmap** — фазы 0–5 с критериями перехода.
4. **Walking Skeleton v0.1** — сборка 2–4 недели.
5. Возврат к вопросам 83–99 (экономика) — **до Foundation**, они блокируют
